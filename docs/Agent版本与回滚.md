# Agent 版本与回滚

## 版本快照包含什么

`POST /agent/{id}/publish` 会生成 `AgentVersion`（V1、V2…），快照内容：

- 名称、描述、系统提示词、欢迎语
- 模型配置（含 thinking / reasoningEffort）
- Agent 能力（流式、函数调用、多模态、自我纠正、写工具策略等）
- 记忆配置、检索配置、占位变量
- **知识库绑定**（含每个库的 retrievalConfig：topK / 阈值 / 模式）
- **技能绑定、工具绑定、子 Agent 绑定**

工作流是独立版本体系（`workflow/publish`），不在 Agent 快照内。

## 回滚语义（已补全）

`POST /api/v1/agent/{id}/versions/{version}/rollback`

- 恢复上述全部字段与绑定，而不是只恢复提示词/模型
- 绑定按快照整体覆盖（知识库/技能/工具/子 Agent），并校验目标是否仍存在/可访问
- 回滚本身会生成一个新版本号（例如回滚 V1 → 生成 V3），不会改写历史
- 写审计日志 `agent.rollback`（from / newVersion）
- 前端入口：Agent 编辑 → 版本 → 回滚（确认后刷新页面）

> 旧版本快照如果缺少某个键（历史数据），对应部分保持现状，不会被清空。

## 部署历史「回滚并部署」

容器部署弹窗 → 部署历史 → 某条 DEPLOY 记录 → 「回滚并部署」：

1. 把 Agent 配置完整回滚到该记录对应的版本（生成新版本）
2. 立即用新配置重新部署容器（令牌保持不变，端口优先复用）
3. 页面刷新，显示新版本

## 端口与令牌稳定性

- 重新部署优先复用原端口；原端口短暂被占用时会等待最多 3 秒再换端口
- 访问令牌在重新部署/发布自动部署时保持不变，只有「重置令牌」才更换

## 验证

- API：创建带知识库/变量的 Agent → 发布 V1 → 改配置并发布 V2 → 回滚 V1
  - 名称/提示词/变量/知识库（含 topK=7、阈值、模式）全部恢复，生成 V3
- UI：部署历史「回滚并部署」→ 配置回到 V1、容器重建、版本 V3、端口复用 19001/19002、令牌不变
- 删除 Agent 会清理容器、部署记录与部署 Key
