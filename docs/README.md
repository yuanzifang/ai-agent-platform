# 文档入口与维护规则

更新时间：2026-11-03

## 1. 单一事实来源

当前状态类文档只保留以下五份，其他批次记录不得再复制状态结论：

| 文档 | 用途 |
|---|---|
| [`交付现状.md`](交付现状.md) | 当前交付状态、测试基线、真实缺口 |
| [`上线差距清单.md`](上线差距清单.md) | 上线优先级与阻塞项 |
| [`P0验收追踪矩阵.md`](P0验收追踪矩阵.md) | 需求 §5.2 P0 逐项证据 |
| [`技术决策记录.md`](技术决策记录.md) | RLS、搜索、双语、文件规模等长期决策 |
| [`故障演练记录.md`](故障演练记录.md) | 最近可复现演练证据 |

这些文档更新时必须写日期、环境、命令/接口和结果；不要只写“已完成”。

## 2. 目录规则

```text
docs/                 当前状态、运维手册、仍在使用的功能说明
docs/archive/         历史批次、一次性验收/压测/长稳记录
docs/fixtures/        测试语料/固定数据
```

归档规则：

- 一次性实跑验收、压测、长稳、上一版本回归、历史基准 → `docs/archive/`
- 被归档文件不再作为当前验收口径；结论必须已经汇总到状态文档
- `docs/archive/README.md` 维护归档索引
- 归档文件不得继续被 README/部署文档引用；必须引用时改为 `docs/archive/...`

## 3. 命名与写作

- 状态文档：`交付现状.md`、`上线差距清单.md`、`P0验收追踪矩阵.md`、`技术决策记录.md`
- 运维手册：保留明确名称，如 `备份与恢复.md`、`大表分区.md`、`用户手册.md`
- 批次记录：使用 `实跑验收`、`压测`、`长稳验收`、`回归`、`基准` 等后缀，归档到 `docs/archive/`
- 文档中引用文件使用相对路径；移动文件时同步更新引用

## 4. 强制检查

CI 执行：

```bash
python3 scripts/check-docs.py
```

检查：

- 五份状态文档存在
- `docs/archive/README.md` 存在
- 已归档批次文件不再留在 `docs/` 根目录
- 根目录不再新增 `*实跑验收.md`、`*长稳验收.md`、`*上一版本回归.md`、`*百文档基准.md`
