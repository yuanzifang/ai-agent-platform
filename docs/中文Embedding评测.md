# 中文 Embedding 模型评测（2026-10-26）

## 结论

在本机 Ollama 上用 10 条中文知识文档、12 条中文查询做小样本召回评测：

| 模型 | 维度 | Recall@1 | MRR | 10 条文档 embedding 耗时 |
| --- | ---: | ---: | ---: | ---: |
| `nomic-embed-text` | 768 | **0.417** | **0.546** | 343ms |
| `bge-m3` | 1024 | **1.000** | **1.000** | 1112ms |

`bge-m3` 在中文短查询和中文知识片段上的召回明显更好，代价是模型更大、首次加载/embedding 更慢。

**建议**：中文为主的知识库优先选择 `bge-m3`。平台现已默认优先 `bge-m3`，
启动时探测 Ollama：未安装 `bge-m3` 但安装了 `nomic-embed-text` 时自动回退，
避免旧环境新知识库不可用。也可显式指定：

```bash
EMBEDDING_MODEL=bge-m3
EMBEDDING_DIMENSIONS=1024
```

## 测试方法

- 10 条中文知识片段：退款、发票、配送、积分、密码重置、数据导出、休假、报销、
  服务器扩容、API 限流；
- 12 条中文口语化查询；
- 用 Ollama `/api/embeddings` 生成文档/查询向量；
- cosine 相似度排序，计算：
  - Recall@1：正确文档排第一的比例；
  - MRR：正确文档排名的倒数均值。

## 固定中文检索黄金集（v1）

为避免只验证“能入库、能检索”，仓库增加了固定中文 QA 集：

- 数据：`docs/fixtures/中文检索黄金集-v1.json`
- 16 条中文知识片段、21 条口语化查询；
- 使用稳定 slug（如 `refund`、`invoice`）关联相关文档，不依赖数据库自增 ID；
- 脚本：`scripts/eval_chinese_retrieval.py`

```bash
# Ollama / OpenAI 兼容 embedding 端点均可
python3 scripts/eval_chinese_retrieval.py \
  --endpoint http://127.0.0.1:11434/v1/embeddings \
  --model bge-m3 \
  --output target/chinese-retrieval.json \
  --min-recall5 0.80 --min-mrr 0.80
```

输出 Recall@1/3/5/10、MRR、nDCG@5 和逐查询排名。切换 embedding 模型、分块策略或
向量库前后，应使用同一份 fixture 和相同 topK 对比；建议把结果 JSON 作为发布附件。

> 该脚本评估 embedding/向量召回本身；平台内的 `RETRIEVAL` 评测步骤还会叠加混合检索、
> 权限过滤和 chunk 切分，两者应结合使用。

## 说明

- 这是小样本评测，不是完整基准；上线前应使用真实知识库、真实用户查询和
  「黄金数据集」做 Recall@K/MRR/NDCG。
- `bge-m3` 模型约 1.2GB，低资源环境仍可保留 `nomic-embed-text`。
- 切换知识库的 embedding 模型后，旧向量会失效，必须触发索引重建。
