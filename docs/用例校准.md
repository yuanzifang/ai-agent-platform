# 用例人工标注与裁判校准

对应“人工闭环”缺口：用例库原有审核/修正，本批次增加回归结果的人工标注队列与 LLM 裁判一致性统计。

## 1. 数据

V52 在 `test_case_run_item` 增加：

- `human_score`：人工评分 0~1
- `human_label`：PASS / FAIL
- `reviewer_id`
- `reviewed_at`
- `review_note`

每条模型回归明细保留 LLM 裁判分 `score`，人工标注独立存储，不覆盖裁判结果。

## 2. 接口

```http
GET /api/v1/cases/calibrations?status=PENDING|DONE|ALL&runId=&page=1&pageSize=20
GET /api/v1/cases/calibrations/stats
PUT /api/v1/cases/calibrations/{itemId}
```

标注请求：

```json
{"humanScore": 1, "humanLabel": "PASS", "note": "人工复核正确"}
```

- `humanLabel` 必填，PASS/FAIL；
- `humanScore` 省略时按标签补 1/0；
- 保存写审计 `case.calibration`；
- 仅 `eval:manage`。

统计：

- `total/labeled/pending`
- `agreementRate`：人工 PASS/FAIL 与裁判 `score>=0.6` 的通过/失败是否一致
- `meanAbsError`：人工分与裁判分的平均绝对差

## 3. UI

用例库工具栏新增「人工标注 / 校准」抽屉：

- 待标注/已标注/全部筛选
- 回归任务、候选模型、问题、候选回答、参考/期望
- 裁判分、人工分、PASS/FAIL、备注
- 一致率/平均分差统计
- 保存后刷新队列

## 4. 已验证

2026-10-21 E2E：

- 回归产生 2 条明细；
- `/cases/calibrations?status=PENDING` 返回待标注；
- PUT 人工 PASS 分=1；
- `/stats` labeled >=1；
- DONE 队列包含刚标注项；
- 后端单测 **51/51**、完整 E2E **29/29**（本批次前）。

## 5. 边界

- 当前每个明细只有**一个**人工标注，没有多人独立标注/共识/分歧队列，`agreementRate` 是“单标注 vs 裁判”，不是 inter-annotator agreement。
- 没有标注任务分配、盲标、抽检、复核人层级。
- 没有按评测数据集/生产 Trace 的抽样入队，只覆盖用例回归明细。
- 校准结果尚未自动调整裁判阈值或 prompt；目前只做统计。
