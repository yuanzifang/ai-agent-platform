# 黄金数据集分层

## 1. 层级

`test_case` 新增：

- `dataset_tier`：CANDIDATE / APPROVED / GOLDEN / ARCHIVED
- `risk_level`：LOW / MEDIUM / HIGH
- `coverage_tags`：JSON 覆盖标签
- `expires_at`：有效期

`APPROVED` 只表示可用于回归；`GOLDEN` 是更高门槛的权威集。

## 2. 晋升规则

`dataset_tier=GOLDEN` 必须同时满足：

- `status=APPROVED`
- 坏例必须有人工期望答案
- 设置 `riskLevel`
- `coverageTags` 非空
- `expiresAt` 不存在或未过期

接口：

```http
PUT /api/v1/cases/{id}
{
  "status": "APPROVED",
  "datasetTier": "GOLDEN",
  "riskLevel": "HIGH",
  "coverageTags": ["安全", "坏例"],
  "expiresAt": "2027-12-31T23:59:59"
}
```

列表：

```http
GET /api/v1/cases?tier=GOLDEN
```

回归：

```http
POST /api/v1/cases/run
{"modelName":"deepseek-flash","tier":"GOLDEN","caseIds":[...]}
```

## 5. 步骤级黄金集（本轮新增）

`eval_dataset_item` 新增：

- `step_type`：`ANSWER` / `REWRITE` / `RETRIEVAL` / `RERANK`
- `expected_payload`：JSON 期望，如 `{"chunk_ids":[11,12]}`、`{"ordered_chunk_ids":[2]}`、`{"rewrite":"...","must_keep":["退款"]}`
- `step_config`：JSON 配置，如 `{"knowledgeBaseId":1,"topK":5,"mode":"hybrid"}`

`eval_result` 新增：

- `step_type`
- `step_passed`
- `step_details`
- `review_status` / `review_note` / `reviewed_by` / `reviewed_at`

当前确定性校验：

- `RETRIEVAL`：chunk 召回率、可选 document 召回、`must_contain` 关键词命中率，默认阈值 0.8
- `RERANK`：首选 chunk 排名 MRR + nDCG，默认阈值 0.5
- `REWRITE`：期望改写文本、必须保留实体、禁止词；模型改写器（模型由步骤配置选择）
  - `stepConfig.localOnly=true` 或 `stepConfig.mode="local"` 时走确定性本地 fallback：不调用模型，只去掉“帮我改写查询”等指令壳并保留原查询实体
  - 单步试跑可用 `stepConfig.model` 指定平台本地 Ollama 模型；已用 `qwen2.5:7b` 真实本地验收（得分 1，热调用约 1.4s），详见 `docs/本地改写模型验收.md`
  - Agent 任务的 REWRITE 优先使用 Agent 的 `modelConfig.modelName`；本地模型标记为 `PLATFORM`，不能绑定 Agent
- `ANSWER`：保留原 LLM 裁判

评测任务会为步骤用例生成独立 Trace Span，`step_details` 保存实际命中/排序/改写结果，不调用外部 JEV。

样本编辑（保留 id，编辑后刷新数据集时间以失效门禁缓存；步骤校验与新增一致）：

```http
PUT /api/v1/eval/datasets/items/{itemId}
{"question":"...","expectedAnswer":"...","scoreCriteria":"...","stepType":"RETRIEVAL","expectedPayload":"{\"chunk_ids\":[11]}","stepConfig":"{\"knowledgeBaseId\":1}"}
```

空字符串的 JSON 字段（`expectedPayload` / `stepConfig`）会自动存为 NULL，避免 MySQL JSON 列拒绝空串。

单步即时评测（不创建任务）：

```http
POST /api/v1/eval/steps/run
{
  "stepType": "RETRIEVAL",
  "query": "退款怎么申请",
  "expectedPayload": "{\"chunk_ids\":[11,12]}",
  "stepConfig": "{\"knowledgeBaseId\":1,\"topK\":5,\"mode\":\"hybrid\"}"
}
```

ANSWER 单步额外传 `agentId`：

```http
POST /api/v1/eval/steps/run
{"stepType":"ANSWER","agentId":1,"query":"只回答OK","expectedPayload":"{\"expectedAnswer\":\"OK\"}","stepConfig":"{\"judgeModel\":\"deepseek-flash\"}"}
```

数据集步骤覆盖：

```http
GET /api/v1/eval/datasets/{id}/step-summary
```

步骤类型目录与样本校验：

```http
GET /api/v1/eval/step-types
```

新增样本时会校验：

- 检索必须有 `knowledgeBaseId` + `chunk_ids`
- 重排必须有 `knowledgeBaseId` + `ordered_chunk_ids`
- 改写必须有 `rewrite` 或 `must_keep`
- `expectedPayload`/`stepConfig` 必须是合法 JSON

覆盖统计额外返回 `missing`，列出数量为 0 的步骤类型。

跨数据集覆盖矩阵：

```http
GET /api/v1/eval/coverage?agentId=1
```

返回每个数据集的 step 计数、缺失类型，以及按步骤类型汇总的 `totalByType/missingTypes`。

任务详情增加 `stepSummary`：按 ANSWER/REWRITE/RETRIEVAL/RERANK 汇总数量、平均分和通过率。

数据集历史趋势：

```http
GET /api/v1/eval/datasets/{id}/trend?limit=10&agentId=1
```

返回最近已完成任务的整体分数、通过率和分步骤指标，用于观察改写/检索/重排是否逐步改善。

评测结果人工复核：

```http
PUT /api/v1/eval/results/{id}/review
{"reviewed": true, "note": "已核对检索证据"}
```

只记录人工确认/备注，不覆盖确定性分数；低分步骤可先由人工确认是否可接受。

任务间分步骤对比：

```http
GET /api/v1/eval/tasks/{id}/compare/{baselineId}
```

返回每步 current/baseline、平均分差、通过率差，以及 `improved/regressed` 类型列表，用于判断检索、重排、改写改动是否造成回归。

预发布门禁同时检查分步通过率：

- 有样本的 ANSWER/REWRITE/RETRIEVAL/RERANK 每一步都需达到门禁阈值
- 任一步低于阈值时阻断发布
- 门禁响应新增 `stepGate.steps/failedSteps/failures`
- `failures` 返回最多 20 条失败样本的 traceId、score、原因和步骤明细
- 没有样本的步骤不阻断
