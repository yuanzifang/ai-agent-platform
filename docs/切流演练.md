# 冷切流与回切演练

脚本：`scripts/pitr-cutover.sh`

目标：验证“停写 → 冷克隆 → 8080 切到临时库 → 业务 smoke → 回切原库/清理”的维护窗口流程。

## 1. 前置

- 后端 jar 已构建。
- 当前 8080 是唯一后端实例；其他实例必须先停止。
- MySQL 使用根账号或具备建库/导库权限的账号。
- 切流期间不要跑迁移、E2E 或其他会写源库的任务。

## 2. 使用

```bash
# dry-run：只打印计划，不动数据库/不停止应用
./scripts/pitr-cutover.sh --jar backend/target/ai-agent-platform-backend-0.1.0-SNAPSHOT.jar

# 冷切流 + smoke + 自动回切
./scripts/pitr-cutover.sh \
  --jar backend/target/ai-agent-platform-backend-0.1.0-SNAPSHOT.jar \
  --apply --yes

# 保留切流（目标实例继续占用 8080，原库保留作为回滚源）
./scripts/pitr-cutover.sh --jar ... --apply --yes --no-rollback

# 当前没有实例时显式允许（仍会启动源库实例做回切）
./scripts/pitr-cutover.sh --jar ... --apply --yes --allow-no-app
```

脚本保证：

- 目标库名必须包含 `_cutover_` / `_pitr_` / `_drill_`，且不能等于源库。
- 停止应用后必须确认 8080 已释放；否则拒绝继续。
- 克隆前后校验源库表数、Flyway 版本；迁移/并发写入导致 schema 变化时中止。
- 新实例必须由脚本启动的 PID 真正占用 8080，且 health=200；不会把旧实例的 health 误当成功。
- 默认执行回切并验证原库 health/login/审计链/Agent 列表；临时库和临时实例自动清理。

## 4. 生产注意事项

- 生产应使用维护窗口、只读/停写确认和独立回滚窗口。
- 必须确认没有其他后端/定时任务/外部写入连接源库。
- 生产建议在切流前创建一次完整备份；本脚本的临时 dump 只用于本次克隆，不是长期备份。
- `--no-rollback` 保留目标实例时，原库仍是回滚源；确认目标库稳定后再决定是否下线原库。
- 真实域名/Ingress/连接池切换仍需在目标环境演练。
