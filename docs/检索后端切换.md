# 检索后端切换（MySQL/ES、pgvector/Qdrant）

更新：2026-10-27

## 默认模式

```yaml
search:
  keyword:
    provider: mysql
vector:
  store: pgvector
```

这是现有生产/开发默认配置，行为与之前一致。

## 关键字检索：MySQL / Elasticsearch

### MySQL

默认使用 `knowledge_chunk` 上的 ngram FULLTEXT 索引：

```text
KEYWORD_SEARCH_PROVIDER=mysql
```

实现：`MysqlKeywordSearchStore`。

### Elasticsearch

```text
KEYWORD_SEARCH_PROVIDER=es
ELASTICSEARCH_URL=http://127.0.0.1:9200
ELASTICSEARCH_INDEX=aap_knowledge_chunks_v1
ELASTICSEARCH_API_KEY=
```

实现：`ElasticsearchKeywordSearchStore` + 轻量 REST 客户端，不引入额外 ES SDK。

索引同步链路：

```text
MySQL knowledge_chunk
  -> knowledge_search_outbox（insert/update/delete 触发器）
  -> KnowledgeSearchOutboxScheduler
  -> Elasticsearch
```

- 首次启用时 worker 会把现有分段排入 outbox，异步建立索引；
- 可手动重建单个知识库：

```http
POST /api/v1/knowledge-base/{id}/search-index/reindex
```

- ES 查询在服务端完成知识库、ACL、有效期过滤；
- 宽泛查询仍需要 ES 分片/副本和足够 CPU；
- ES 不可用时，业务会走关键字 LIKE 兜底，不会让检索接口直接 500。

索引 mapping 使用 ngram analyzer，兼容中文检索；索引名为单索引 + `tenant_id` 过滤。

## 向量检索：pgvector / Qdrant

### pgvector

```text
VECTOR_STORE=pgvector
```

现有 `VectorRepository` 实现，保留 partial HNSW、HNSW、物化过滤集等全部能力。

### Qdrant

```text
VECTOR_STORE=qdrant
QDRANT_URL=http://127.0.0.1:6333
QDRANT_API_KEY=
QDRANT_COLLECTION_PREFIX=aap
```

实现：`QdrantVectorStore`，按租户 + 维度创建 collection：

```text
aap_{tenantId}_{dimensions}
```

payload 保存正文、知识库/文档/chunk ID、ACL、有效期和原始 metadata；检索过滤在 Qdrant 服务端完成。

支持：

- 租户独立 collection；
- Cosine 相似度；
- ACL/tenant_visible/有效期过滤；
- 文档删除、知识库删除；
- 文档有效期同步；
- ACL 同步；
- chunk 内容/向量修正；
- 文档向量复制。

Qdrant 默认不需要 partial HNSW；`reconcilePartialIndexes` 返回空操作，索引状态接口返回 Qdrant provider。

### Milvus 扩展点

已保留：

```java
public interface MilvusVectorStore extends VectorStore {
}
```

后续实现 `VectorStore` 并注册 `vector.store=milvus` Bean 即可，不需要修改业务层。

## 运维注意事项

- 默认 `mysql + pgvector`，切换前先在测试环境验证；
- ES outbox 触发器会记录 MySQL 分段变更；ES 关闭时 outbox 会积累，开启后由 worker 消费；
- Qdrant/ES 都需要额外网络、磁盘、备份和监控；
- 已验证：默认配置启动、ES 配置启动、Qdrant 配置启动、MySQL outbox migration/trigger、抽象层编译和全量单测；
- 已用本地真实 Elasticsearch 8.15 验证 outbox trigger → worker → 索引 → KEYWORD 查询；
- 已用本地真实 Qdrant 验证 saveBatch、ACL 过滤和向量查询（`QdrantVectorStoreIT`）；
- 尚未用真实 ES/Qdrant 跑大规模/高可用/故障恢复；生产切换必须补集群容量、副本、备份和 ACL 回归。
