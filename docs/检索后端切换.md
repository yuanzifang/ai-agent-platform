# 检索后端切换（MySQL/ES、pgvector/Qdrant）

更新：2026-10-27

## 知识库级选择

每个知识库保存两个字段：

```text
knowledge_base.search_backend  = MYSQL / ES
knowledge_base.vector_backend  = PGVECTOR / QDRANT
```

- 新建/编辑知识库的界面提供这两个下拉；
- 默认仍是 `MYSQL + PGVECTOR`；
- 已有文档时禁止切换向量后端，避免不同后端数据不一致；
- `GET /api/v1/knowledge-base/retrieval-backends` 返回当前可用后端；
- 未启用 ES/Qdrant 时，对应选项不可用，后端也会拒绝创建。

## 关键字检索：MySQL / Elasticsearch

### MySQL

默认使用 `knowledge_chunk` 上的 ngram FULLTEXT 索引：

```text
KEYWORD_SEARCH_PROVIDER=mysql
```

实现：`MysqlKeywordSearchStore`。

### Elasticsearch

```text
SEARCH_ES_ENABLED=true
ELASTICSEARCH_URL=http://127.0.0.1:9200
ELASTICSEARCH_INDEX=aap_knowledge_chunks_v1
ELASTICSEARCH_API_KEY=
```

`KEYWORD_SEARCH_PROVIDER` 只决定新建知识库的默认值；启用 ES 由 `SEARCH_ES_ENABLED` 控制。

实现：`ElasticsearchKeywordSearchStore` + 轻量 REST 客户端，不引入额外 ES SDK。

索引同步链路：

```text
MySQL knowledge_chunk
  -> knowledge_search_outbox（insert/update/delete 触发器）
  -> KnowledgeSearchOutboxScheduler
  -> Elasticsearch

触发器只在 search.es.enabled=true 且该知识库 search_backend='ES' 时写入；
ES 关闭时 outbox 不再持续积累。
```

- 首次启用时 worker 会把现有分段排入 outbox，异步建立索引；
- 可手动重建单个知识库：

```http
POST /api/v1/knowledge-base/{id}/search-index/reindex
```

- ES 查询在服务端完成知识库、ACL、有效期过滤；
- 宽泛查询仍需要 ES 分片/副本和足够 CPU；
- ES 不可用时，业务会走关键字 LIKE 兜底，不会让检索接口直接 500。

索引 mapping 使用 ngram analyzer，兼容中文检索；索引名为单索引 + `tenant_id` 过滤。

## 向量检索：pgvector / Qdrant

### pgvector

```text
VECTOR_STORE=pgvector
```

现有 `VectorRepository` 实现，保留 partial HNSW、HNSW、物化过滤集等全部能力。

### Qdrant

```text
VECTOR_QDRANT_ENABLED=true
QDRANT_URL=http://127.0.0.1:6333
QDRANT_API_KEY=
QDRANT_COLLECTION_PREFIX=aap
```

`VECTOR_STORE` 只决定新建知识库的默认值；启用 Qdrant 由 `VECTOR_QDRANT_ENABLED` 控制。

实现：`QdrantVectorStore`，按租户 + 维度创建 collection：

```text
aap_{tenantId}_{dimensions}
```

payload 保存正文、知识库/文档/chunk ID、ACL、有效期和原始 metadata；检索过滤在 Qdrant 服务端完成。

支持：

- 租户独立 collection；
- Cosine 相似度；
- ACL/tenant_visible/有效期过滤；
- 文档删除、知识库删除；
- 文档有效期同步；
- ACL 同步；
- chunk 内容/向量修正；
- 文档向量复制。

Qdrant 默认不需要 partial HNSW；`reconcilePartialIndexes` 返回空操作，索引状态接口返回 Qdrant provider。

### Milvus 扩展点

已保留：

```java
public interface MilvusVectorStore extends VectorStore {
}
```

后续实现 `VectorStore` 并注册 `vector.store=milvus` Bean 即可，不需要修改业务层。

## 运维注意事项

- 默认 `mysql + pgvector`，切换前先在测试环境验证；
- ES outbox 触发器会记录 MySQL 分段变更；ES 关闭时 outbox 会积累，开启后由 worker 消费；
- Qdrant/ES 都需要额外网络、磁盘、备份和监控；
- 已验证：默认配置启动、ES 配置启动、Qdrant 配置启动、MySQL outbox migration/trigger、抽象层编译和全量单测；
- 已用本地真实 Elasticsearch 8.15 验证 outbox trigger → worker → 索引 → KEYWORD 查询；
- 已用本地真实 Qdrant 验证完整知识库上传→embedding→Qdrant 写入→VECTOR 查询，pgvector 该 KB 行数为 0；
- 已验证同一实例内 `MYSQL` KB、`ES` KB、`PGVECTOR` KB、`QDRANT` KB 并存；
- 尚未用真实 ES/Qdrant 跑大规模/高可用/故障恢复；生产切换必须补集群容量、副本、备份和 ACL 回归。

## 本地常驻容器

ES 使用持久卷并设置 `restart=always`：

```bash
docker run -d --name aap-es-local --restart=always --memory=1g \
  -p 9200:9200 \
  -e discovery.type=single-node \
  -e xpack.security.enabled=false \
  -e ES_JAVA_OPTS='-Xms512m -Xmx512m' \
  -v aap-es-data:/usr/share/elasticsearch/data \
  docker.elastic.co/elasticsearch/elasticsearch:8.15.0
```

Qdrant 按需启动，不常驻：

```bash
docker run -d --name aap-qdrant-local --memory=256m \
  -p 6333:6333 \
  -v aap-qdrant-data:/qdrant/storage \
  qdrant/qdrant:latest
```

后端本地启动需带：

```bash
SEARCH_ES_ENABLED=true
ELASTICSEARCH_URL=http://127.0.0.1:9200
VECTOR_QDRANT_ENABLED=false
```

验证过：ES 容器重启后索引仍可查询；Qdrant 验证完成后容器已移除，数据卷保留。

## 平台管理页维护数据源

平台管理员页面（系统设置 → 基础设施）可以维护：

- MySQL 主库 URL / 用户 / 密码；
- Redis host / port / 密码；
- PostgreSQL/pgvector URL / 用户 / 密码；
- MinIO endpoint / access key / secret / bucket；
- Elasticsearch enabled / URL / index / 认证；
- Qdrant enabled / URL / collection prefix / API key。

保存位置：

```text
${PLATFORM_INFRA_CONFIG:-config/application-platform.yml}
```

该文件由启动期 `LocalInfraConfigPostProcessor` 以高优先级加载，因此下次重启可以覆盖环境变量；
包含凭据，已加入 `.gitignore`，文件权限设为 0600。**保存后必须重启后端才生效**。

密码/API Key 以 AES-GCM 密文（`v1:` 前缀）保存，启动时解密后再交给 Spring；`.bak` 备份同样加密并保持 0600。
生产环境必须配置稳定且独立的 `AES_KEY`（至少 32 字节随机值），不要依赖 `JWT_SECRET` 兜底；更换 `AES_KEY` 后旧密文无法解密，后端会启动失败并提示检查密钥。
历史明文配置保持兼容，下一次从平台页保存时自动迁移为密文。

敏感字段留空表示保留当前值；页面不回显密码/API Key。

部署挂载：

- Compose 使用命名卷 `platform-config` 挂到容器 `/app/config`，容器重建后平台页保存的配置仍在；
- Helm 可设置 `platformInfra.existingSecret`，把包含 `application-platform.yml` 的 Secret 只读挂到同一路径；
  多副本下平台页不能写只读 Secret，应更新 Secret 后滚动重启。

### Agent 资源 Profile

平台管理员维护 `retrieval_resource_profile`，普通用户在 Agent 编辑页只能选择启用的 Profile：

```text
Agent -> resourceProfileId -> 平台资源 Profile
```

Agent 的请求里不包含 MySQL/Redis/PG/ES/Qdrant 地址或密码；知识库绑定仍由 Agent 维护，
每个知识库的实际检索后端继续由知识库配置决定。

## TopK 约束

- 知识库保存 `default_top_k`（默认 5）和 `max_top_k`（默认 20）；
- Agent-KB 绑定可以覆盖 topK；
- 运行时以绑定值为起点，缺失时继承知识库默认值，最终截断到知识库上限；
- 知识库测试检索接口同样受上限约束。

## Resource Profile 校验

选择资源 Profile 后，Agent 绑定的知识库必须与其后端组合一致：

```text
Profile: MySQL/pgvector  -> 只能绑定 MySQL/pgvector 知识库
Profile: ES/Qdrant       -> 只能绑定 ES/Qdrant 知识库
```

不一致时后端拒绝保存；前端会禁用不匹配 KB 并标记。

基础设施保存前支持连接测试，并在覆盖前保留上一版 `.bak` 文件。

本地 Qdrant 按需启停：

```bash
scripts/qdrant-local.sh start
scripts/qdrant-local.sh stop
```

启动后到平台基础设施页启用 Qdrant 并重启后端；停止会移除容器但保留 `aap-qdrant-data` 卷。
