# 全局搜索全文索引

日期：2026-10-31

## 现状

顶栏统一搜索仍复用各模块现有权限查询，不做跨模块数据旁路；关键词匹配已从多表 `LIKE` 切换为 MySQL InnoDB FULLTEXT。

新增迁移：

```text
backend/src/main/resources/db/migration/V130__global_search_fulltext.sql
```

索引：

```text
agent_registry(name, description)     ft_agent_search
knowledge_base(name, description)     ft_kb_search
test_case(question, expected_answer)  ft_case_search
tool_registry(name, description)      ft_tool_search
```

使用 MySQL `ngram` parser，支持中文分词。

## 查询变化

- Agent 列表：`MATCH(name, description)` 替代 `name LIKE`
- 知识库列表：`MATCH(name, description)` 替代名称/描述 `LIKE`
- 用例列表：`MATCH(question, expected_answer)` 替代问题 `LIKE`
- 工具列表：新增 `searchVisible` FULLTEXT 查询；分类/类型过滤保持不变

权限过滤、租户过滤、私有 Agent 可见性、知识库 ACL、点击反馈和名称纠错逻辑均保留。

## 回归

新增 API 用例：

```text
frontend/e2e/api.spec.ts
全局搜索支持名称和描述全文匹配
全局搜索知识库和工具描述全文匹配

```

测试分别验证 Agent、知识库、工具、用例的全文关键词能命中，不是只有名称或单表生效。

## 注意

- MySQL FULLTEXT 的自然语言模式适合当前站内搜索规模；大规模数据集仍需评估专用搜索集群。
- 单字符查询仍由 SearchService 的既有短查询策略跳过。
- 生产数据库执行迁移前应确认存储引擎和 ngram parser 可用。
