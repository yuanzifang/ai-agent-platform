# 授权安全测试报告（本机预检，非独立第三方渗透）

日期：2026-10-27  
目标：本机开发环境 `http://127.0.0.1:8080`、Vite 前端 `http://127.0.0.1:5173`、Agent 运行时网关 `http://127.0.0.1:19001`  
测试性质：开发者授权的自动化 + 手工验证，用于上线前发现和修复问题；**不等同于独立第三方渗透测试报告**。  
测试边界：只做只读/低影响请求；未做破坏性 DoS、未尝试真实外部账号接管、未使用生产凭据。

## 1. 结论

测试范围内未发现可直接绕过认证、跨租户读取或任意命令执行的高危漏洞。发现 2 个需要生产网络边界配合的中风险项、2 个低风险/配置项，以及 1 个开发环境 SSRF 配置风险。所有应用级问题已记录，生产部署必须保持 `TOOL_ALLOW_PRIVATE=false` 且不直接暴露后端管理端口。

## 2. 测试范围与方法

覆盖：

- 认证：匿名访问、伪造 JWT、`alg=none`、登录注入字符、超长用户名
- 授权：租户隔离、同租户越权、平台管理接口、伪造 `X-Tenant-Id`
- 接口：Agent、会话、知识库、用例、统一网关、Open API、MCP
- SSRF：知识库 URL 导入的环回/链路本地/`file://` 输入
- 管理面：Actuator、OpenAPI/Swagger、内部 Alertmanager webhook
- 浏览器边界：CSP、X-Frame-Options、nosniff、Referrer-Policy、CORS 预检
- 限流：租户 API 限流触发
- 已有工具链：gitleaks、Trivy、npm audit、CodeQL、依赖许可证策略

### 3.2 发现

#### SEC-01 中（已修复）：开发配置下 URL 导入可访问环回地址（SSRF）

- 证据：`TOOL_ALLOW_PRIVATE=true` 时，`POST /api/v1/knowledge-base/1/documents/url` 使用 `http://127.0.0.1:8080/actuator/health` 返回 200，并创建文档。
- 影响：可让后端访问本机/内网 HTTP 服务，读取响应并落库；生产若误开 `TOOL_ALLOW_PRIVATE`，存在 SSRF 风险。
- 现有防护：`NetworkPolicyService.validateHttpUrl` 在 `allow-private=false` 时阻断环回、链路本地、私网、ULA；重定向逐跳校验；`file://` 拒绝。
- 生产状态：Compose/Helm 默认 `TOOL_ALLOW_PRIVATE=false`；本次本机后端使用开发默认 true。
- 处置：测试文档已删除；已将用户可控 URL 导入改为调用 `validatePublicHttpUrl`，**无条件禁止环回/内网/链路本地/元数据地址**，不再受 `TOOL_ALLOW_PRIVATE` 影响；重定向逐跳复用同一校验。生产仍需保持 false，并在网络层禁止后端出站到私网/元数据地址。
- 回归：`NetworkPolicyServiceTest#publicValidatorBlocksPrivateEvenWhenGlobalAllows`。

#### SEC-02 中（已提供应用层 token）：Actuator Prometheus 与内部 webhook

- `/actuator/prometheus` 无认证返回 200，暴露指标标签（agent_id/tenant_id 等）。
- `/internal/alertmanager` 无认证返回 200；若后端端口直接暴露，可被滥用触发告警。
- 设计意图：Nginx/Ingress 不反代 `/internal/**`，K8s/Compose 只在内网抓取；但本机直接访问 8080 可命中。
- 处置：`/internal/alertmanager` 已支持可选 `X-Internal-Token` 共享密钥；配置 `ALERT_WEBHOOK_INTERNAL_TOKEN` 后，未携带或错误 token 返回 403。`/actuator/prometheus` 已支持可选抓取 token（`METRICS_SCRAPE_TOKEN`，请求头 `X-Metrics-Token` 或 Bearer）；留空保持旧行为。生产应设置 token，并让 Prometheus 使用 `authorization.credentials_file` 发送同一 token；同时只暴露前端/Ingress，后端管理端口绑定内网，Nginx 已显式拒绝 `/actuator/**`、`/internal/**`。

#### SEC-03 低：开发环境 OpenAPI/Swagger 默认开放

- `/v3/api-docs`、`/swagger-ui/index.html` 在开发默认开启（`API_DOCS_ENABLED=true`）。
- 生产 Chart 默认 `apiDocsEnabled=false`；需确认所有生产环境显式关闭并验证 401/404。

#### SEC-04 低：跨域预检返回 401

- 后端未配置 CORS，非 same-origin 浏览器调用不可用；本项目前端走同源 Nginx 代理，不构成漏洞，但对外 API 场景需明确 CORS 策略。

## 4. 本轮加固记录（2026-10-27）

- URL 导入：新增 public-only 校验，开发环境 `TOOL_ALLOW_PRIVATE=true` 也不能导入环回/内网 URL；重定向逐跳校验。
- 内部 webhook：`POST /internal/alertmanager` 支持 `X-Internal-Token`，Compose/Helm 已增加 `ALERT_WEBHOOK_INTERNAL_TOKEN` 配置位；留空兼容旧部署，生产必须设置。
- 部署边界：Chart 默认 `apiDocsEnabled=false`、`toolAllowPrivate=false`；后端端口未在对外 Ingress 暴露；前端 Nginx 显式拒绝 `/actuator/**`、`/internal/**`。Prometheus 抓取 token 已实现，但 Prometheus 配置需同步发送 token。
- 实测（隔离实例，`TOOL_ALLOW_PRIVATE=true`）：URL 导入 `127.0.0.1`、`169.254.169.254` 均返回 400；`/internal/alertmanager` 无 token/wrong token 返回 403，正确 token 返回 200。
- 实测（隔离实例，`METRICS_SCRAPE_TOKEN=metrics-secret`）：`/actuator/prometheus` 无 token/错误 token 返回 403，`X-Metrics-Token`/Bearer 正确返回 200，`/actuator/health` 无 token 仍为 200。
- Prometheus 示例：
  ```yaml
  scrape_configs:
    - job_name: ai-agent-backend
      metrics_path: /actuator/prometheus
      authorization:
        type: Bearer
        credentials_file: /etc/prometheus/metrics-token
      static_configs:
        - targets: ["backend:8080"]
  ```
  文件内容必须与 `METRICS_SCRAPE_TOKEN` 一致；未设置 token 的旧部署保持无认证。

## 10. 上线建议

1. 生产 NetworkPolicy/Ingress 阻断 `/actuator/**`、`/internal/**` 的外网访问。
2. `TOOL_ALLOW_PRIVATE=false`，并配置 `TOOL_ALLOWED_HOSTS` 出口白名单。
3. `API_DOCS_ENABLED=false` 并加启动/CI 断言。
4. 对 URL 导入增加目标 IP 复检（DNS rebinding）和统一出站代理。
5. 真实第三方渗透报告需覆盖认证、租户、SSRF、文件解析、网关和 Agent 运行时镜像。
