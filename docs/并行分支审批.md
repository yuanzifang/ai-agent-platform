# 并行分支审批

## 语义

采用“并行网关前置审批”：

1. 执行 PARALLEL 前，收集所有分支内可达的 APPROVAL 节点；
2. 生成一个统一的并行审批（不是每条分支各暂停）；
3. 审批通过后，分支内 APPROVAL 节点以已批准通道通过；
4. 分支继续执行，State 合并到 JOIN。

这避免了多个分支并发暂停/恢复时无法确定分支游标的问题。

## 验证

E2E：

```text
START → PARALLEL
  ├─ APPROVAL(A) → STATE(pa)
  └─ APPROVAL(B) → STATE(pb)
→ JOIN → END
```

- 运行先进入 `WAITING_APPROVAL`
- 审批箱生成“并行分支审批（2 项）”
- 平台管理员审批通过
- 运行 `SUCCESS`，`state.pa/pb` 均存在
- 完整 E2E 34/34、单测 52/52

## 边界

- 审批是**网关前置**，不是在分支执行中途暂停；审批通过后才执行分支。
- 审批节点及分支内嵌套 PARALLEL 的 APPROVAL 会被收集；条件分支的两条路径都会被收集。
- 并行分支内 LOOP 已支持未超限场景并合并 State；
- 并行启动前会按 `items`/`maxIterations` 预检分支内 LOOP：超限项加入同一个网关审批，审批通过后分支 LOOP 一次放行全部批次，不再中途暂停或直接失败；
- 预检依赖运行时能解析出 items（显式数组或 `{{input}}`）；分支前序节点动态生成的 items 可能无法预判，此时仍返回明确错误；
- 不提供“只恢复某个分支”的细粒度游标。
