## 矩阵

| P0 验收项 | 自动化/可重复证据 | 手工证据 | 当前状态 | 缺口 |
|---|---|---|---|---|
| Compose 实际 `up`、Helm 实际 `install` | 部署模板与配置检查：`docker compose config`、`helm lint`、`helm template`；k3d/Helm 演练记录 | `docs/Compose实跑验收.md`、`docs/Helm实跑验收.md`、`docs/交付现状.md` | 本地通过；真实生产未验收 | 真实域名/CA、托管云资源、生产 metrics-server、生产维护窗口切流 |

| 技能脚本容器级隔离 | `ScriptRunnerDockerIT`；`SkillRuntime...` 单测；CI Docker IT 开关 | `docs/技能脚本沙箱.md`、`docs/交付现状.md` | 容器沙箱能力通过（`--network none`、CPU/内存/PID、cap-drop） | 默认仍为 process；镜像 digest 固定、执行审计增强未完成 |

## 运行入口

```bash
# 部署模板静态检查
docker compose config
helm lint deploy/helm/ai-agent-platform
helm template aap deploy/helm/ai-agent-platform -n aap

# 容器脚本沙箱 IT（需要 Docker）
cd backend
mvn -q -Dtest=ScriptRunnerDockerIT -Dskill.docker.it=true test

# 用例库/校准相关 API E2E
cd frontend
./node_modules/.bin/playwright test e2e/api.spec.ts --grep '用例库|校准'
```

## 结论

P0 三项都有证据，但只有部分实现自动化闭环：

- Compose/Helm：手工验收为主，模板检查可自动化，生产环境不可本地替代
- 标注/校准：有后端与 E2E 覆盖，仍需真实标注长期一致性
- 脚本沙箱：有真实 Docker IT，但默认运行模式和镜像供应链仍需收口

因此不能仅凭本表宣称“P0 100% 自动化通过”。真实生产验收和标注团队验证仍是外部依赖。
