# 审计归档与链锚点

对应需求 3.10：审计日志不可篡改、保留周期可配置（默认 180 天），日志量过大时归档。

V50 增加：

- `audit_operation_archive`：旧分区审计记录归档表
- `audit_chain_checkpoint`：每个租户、每个已裁剪分区的链锚点

## 1. 为什么需要锚点

`audit_operation` 是哈希链：每条 V2 记录的 `prev_hash = H(前一条 hash + 本条字段)`。`/audit/verify` 默认从 `GENESIS` 开始逐条校验。

直接删除旧分区会让当前最早记录的 `prev_hash` 指向已删除记录，导致校验失败。因此裁剪前保存：

```text
tenant_id + partition_name + last_removed_id + last_removed_hash
```

`verifyChain` 只采用“对应分区已经不存在”的最新锚点。若 `DROP PARTITION` 失败、分区仍存在，则忽略该锚点，自动退回到更早的锚点。

## 2. 归档流程

`AuditArchiveService` 每日 04:10（可配）执行：

1. 选出整个月都早于保留截止日的审计月分区；
2. `INSERT IGNORE ... SELECT` 写入 `audit_operation_archive`；
3. 按 `(id, created_at)` join 校验每条源记录都已归档；
4. 对每个租户取该分区最后一条记录，写入 `audit_chain_checkpoint`；
5. 校验通过才 `ALTER TABLE audit_operation DROP PARTITION`；
6. 失败停止后续删除；`pmax` 永不自动删除。

保留窗口为 **180~210 天**（按整月裁剪，不拆月）。

## 3. 配置

```yaml
audit:
  archive:
    enabled: ${AUDIT_ARCHIVE_ENABLED:true}
    retention-days: ${AUDIT_RETENTION_DAYS:180}
    cron: ${AUDIT_ARCHIVE_CRON:0 10 4 * * *}
```

要求：

- 应用账号需要 `SELECT / INSERT / ALTER`（`DROP PARTITION`）权限。
- 归档表本身当前不自动清理；合规保留更久时需冷存储/导出。
- 审计记录包含敏感操作详情，归档表与备份必须按生产数据保护。

## 4. 手动触发

仅平台管理员：

```bash
curl -X POST http://127.0.0.1:8080/api/v1/platform/maintenance/audit-archive \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "X-Tenant-Id: 1"
```

会写审计 `audit.archive`。返回：

```json
{
  "retentionDays": 180,
  "cutoff": "2026-04-23",
  "archivedRows": 2,
  "droppedPartitions": 3,
  "partitions": ["p202601", "p202602", "p202603"],
  "skipped": false
}
```

非平台管理员返回 403；同一时刻只允许一个归档任务。

## 5. 校验与查询

裁剪后 `/audit/verify` 仍返回 `valid=true`，并增加：

```json
{
  "total": 2,
  "checked": 2,
  "anchorPartition": "p202601",
  "valid": true
}
```

归档记录查询：

```sql
SELECT id, tenant_id, op_type, object_type, object_id, op_result, prev_hash, created_at, archived_at
FROM audit_operation_archive
WHERE tenant_id = ?
ORDER BY id DESC
LIMIT 50;
```

当前活动的哈希链校验只覆盖未归档记录 + 锚点；归档段的哈希记录仍保留在归档表中，可离线校验。

## 6. 已验证

2026-10-20 副本库构造独立租户 `tenant=99`：

- 3 条 V2 审计记录（2 条 2026-01 + 1 条 2026-10），裁剪前 `/audit/verify`：`valid=true, checked=3`；
- 手动归档：`archivedRows=2`，`droppedPartitions=3`（p202601..p202603，其中空分区一并清理）；
- 裁剪后 `/audit/verify`：`valid=true, checked=2, anchorPartition=p202601`；
- 归档接口自身的审计记录继续接链；
- `audit_operation_archive` 2 行，`audit_chain_checkpoint` 记录 p202601 / last_removed_id=10002。

真实库：

- Flyway V50 完成，耗时 25ms；归档表/锚点表创建成功；
- 现有审计 226 条链有效，anchor=null；
- 完整 E2E **28/28**，单测 **48/48**；
- V50 后备份 + 恢复演练：MySQL **80 张表**校验和不一致 0（审计 226），PgVector 2 表一致，备份 168K。

## 7. 边界

- 归档表的二级保留/冷存储导出未实现。
- 没有前端审计归档查询/恢复入口。
- 2026-01 之前或进入 `pmax` 的审计不会自动归档。
- 锚点表不自动清理；每个租户每月最多一行。
- 大分区 `INSERT SELECT`/`DROP PARTITION` 的 I/O 未压测，生产建议低峰执行。
- Compose/Helm 未实跑。
