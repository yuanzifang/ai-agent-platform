# 监控闭环

## 链路

```text
Backend/Agent
  ├─ /actuator/prometheus ──> Prometheus ──> Alertmanager
  │                                      └─> alert-relay ──> 钉钉/邮件
  ├─ 容器日志 / logs/backend.log ──> Promtail ──> Loki
  └─ OTLP Traces ──> OTel Collector ──> Tempo

MySQL / Redis / PostgreSQL
  └─ exporter ──> Prometheus

Grafana
  ├─ Prometheus：Overview / Database
  ├─ Loki：Logs
  └─ Tempo：Trace 查询
```

## 本地组件

| 组件 | 端口 | 说明 |
|---|---|---|
| Prometheus | `9090` | 指标、规则、告警 |
| Alertmanager | `19093` | 本地路由到 relay |
| alert-relay | `18099` | 钉钉/邮件投递、ACK/升级 |
| Loki | `3100` | 日志存储 |
| Promtail | `9080` | Docker 容器 + 原生 backend 文件日志 |
| Tempo | `3200` | Trace 存储 |
| OTel Collector | `4317/4318` | OTLP 接收 |
| Grafana | `3000` | 看板/Explore |

本地 native backend 日志写入 `logs/backend.log`，由 `deploy/observability/promtail.native.yml` 采集。
Compose 部署使用 `deploy/observability/promtail.yml`，直接采集 Docker 容器日志。

## Prometheus 多副本 + Thanos

`deploy/observability/ha/docker-compose.yml` 提供：

- Prometheus A/B 独立 TSDB
- nginx `19096` 代理两个副本
- 两个副本都抓 backend/MySQL/Redis/PostgreSQL
- Thanos sidecar A/B 上传 MinIO `thanos` bucket
- Thanos Query `19097` 聚合两个副本和 Store Gateway
- 停掉一个 Prometheus/sidecar 后，Query 仍可返回另一个副本的数据
- Thanos Compactor 运行中，raw/5m/1h 保留分别为 7/30/90 天

本地验证：

- 双副本 4/4 targets up
- Thanos Query `up` 返回 4 个指标
- S3 出现 Prometheus block（`meta.json`、`chunks`、`index`）
- 停掉一个副本后 Query 仍成功
- Compactor `/ready` 200，读取 18 个 block 并执行 downsampling/retention 检查

长期存储模板：

- `deploy/observability/ha/thanos-objstore.example.yml`
- 真实凭据只放本机 `runtime/observability/thanos-objstore.yml`，不提交

当前仍是单机 MinIO，生产需要对象存储高可用和多故障域。

## Loki 3 节点本地验证

`deploy/observability/ha/loki-tempo/docker-compose.yml` 提供：

- Loki 3 节点，memberlist 组网
- S3 `loki-ha` bucket
- nginx LB `23100`
- 独立节点端口 `23101`–`23103`

本地验证：

- 节点可启动并加入 memberlist
- LB 写入 push 204
- LB 查询命中日志
- S3 出现 Loki chunk/index
- 停掉一个节点后，LB 查询仍成功

注意：测试中一个节点 `/ready` 仍返回 503，节点间 gossip 有超时日志；这是本地资源/单进程多角色配置的边界，生产需要拆 distributor/ingester/querier 并做容量规划。

Tempo 3 节点模板同样放在 `loki-tempo/tempo-compose.yml`。本地验证：

- 3 节点启动并加入 memberlist
- 通过节点 OTLP 写入 trace，LB 查询成功
- 停掉一个节点后，LB 查询该 trace 返回 404
- 说明单进程多角色并未实现真正的查询级故障切换；生产必须拆 Tempo querier/ingester，并配置正确的 ring/replication
