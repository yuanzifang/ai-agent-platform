# 农业知识库入库清洗与切块规范

日期：2026-11-03

## 结论

这次农业问答的优化证明：

> **检索和重排的上限，主要由入库前的数据质量决定。**

标准答案即使被召回，如果它和站点导航、标题、发布时间、趋势预报混在同一个 chunk 里，reranker 和 7B 模型都会被干扰。只在检索后做清洗、只在 topK 内重排，收益有限。

因此下一阶段应把工作前移到**解析 → 清洗 → 切块 → 入库**，而不是继续先调 reranker。

## 一、入库前必须清洗的内容

### 1. 站点模板和导航

需要删除：

- `中国农业农村信息网_...`
- `无障碍`
- `农芯慧答`
- `中华人民共和国农业农村部`
- `首页 机构 资讯 数据 生产 信息化 专题 视频`
- `首页>生产>专项监测>作物病虫害`
- `字体：[大 中 小]`
- `打印`
- `分享:`
- `高级检索`

处理原则：

- 站点导航不能进入正文 chunk
- 不能进入 embedding 文本
- 不进入引用摘要
- 如果整段只有导航，直接丢弃

### 2. 标题和时间来源

- 文档标题单独存 metadata，不反复插入正文
- 发布时间、来源、作者单独存 metadata
- 正文中重复出现的标题只保留一次
- 不要为了检索把“怎么防治”等标题词重复拼进正文

### 3. 重复和碎片

- 去掉页面顶部/底部的重复模板
- 去掉连续空行、重复分隔线
- 合并被换行打断的短句
- 表格、图注单独标记，不要和正文段落混切

### 4. Section 类型

每个 chunk 应带 sectionType，至少区分：

- `forecast`：预测、趋势、发生动态
- `action`：防治措施、用药、田间管理
- `background`：背景、危害、症状
- `policy`：政策、方案目标
- `table`：表格
- `other`

检索时根据用户意图使用：

- “怎么防治/用什么药/怎么办” → 优先 `action`
- “发生趋势/会不会发生” → 允许 `forecast`
- “怎么识别/症状” → `background`

## 二、切块规范

当前问题：

- 子块约 500 字符，接近 reranker 512 token 限制
- 首块包含站点导航，正文有效长度被压缩
- 标题、导航、预测、措施可能混在同一块

建议：

1. 先清洗，再切块
2. 子块按 **300～500 tokens** 控制，不用固定字符数
3. 子块重叠约 50 tokens，避免切断完整措施
4. 表格块单独切，单块不超过 1500 字符
5. 父块约 1500～2000 字符，只用于上下文，不直接参与 embedding
6. embedding 文本只包含：
   - 标题路径
   - 清洗后的正文
   - sectionType
   - 不含导航、时间、来源、字号
7. 子块必须保留：
   - documentId
   - chunkIndex
   - parentIndex
   - pageFrom/pageTo
   - sectionType

## 三、检索和重排的边界

- **召回优先**：先保证相关 action 片段进入候选，再谈重排
- 重排候选池至少 10 条，不能只在最终 topK 里重排
- 重排结果必须保留最低分阈值
- 不要在 Prompt 中写“必须按最高分文档回答”
- 7B 对上下文顺序敏感，引用顺序变化会改变答案
- 评测必须同时看：
  - 15 道失败题子集
  - 完整 60 题
  - 多轮裁判，避免单次 2.5 裁判波动

## 四、程序改造清单

### P0：入库清洗

新增 `ContentCleaner`（或 `KnowledgeContentCleaner`）：

- 输入：解析后的 Markdown/HTML 文本
- 输出：清洗后的正文 + metadata
- 规则：
  - 站点模板正则
  - 导航块识别
  - 标题去重
  - 时间/来源/字号/打印/分享移除
  - 空白归一化
- 在 `MarkdownChunker.split()` 之前执行
- 补单元测试：导航清洗、标题去重、表格保留、正文不丢失

### P1：Section 标注

- 在 chunk metadata 增加 `sectionType`
- 对“预测/趋势”和“防治措施”分别标记
- 检索配置支持 `sectionType` 过滤
- 农业 Agent 对“怎么防治”类 query 优先/只召回 `action`

### P1：重新入库和召回审计

- 对 157 篇文档重新解析、清洗、切块
- 检查：
  - chunk token 分布
  - 导航/模板 chunk 比例
  - 500 token 以上 chunk 数量
  - recall@10 / recall@50
  - 引用是否命中对应作物和 section
- 保留旧版本，支持回滚

### P2：重排

- 清洗和 section 完成后再开启 reranker
- 候选池 10～20
- rerankTopN 3
- rerankScoreThreshold 可配
- 按完整 60 题验收，不以 15 题子集作为唯一依据

## 五、验收标准

- 导航/模板 chunk 比例：接近 0
- 500 token 以上 chunk：除表格外接近 0
- “怎么防治”问题 Top 10 中至少 1 条 `action` 片段
- recall@10 明显高于当前
- 完整 60 题通过率 ≥ 0.75
- 引用中跨作物/跨病害文档明显减少

## 六、经验记录

1. **重排不能补召回**：候选里没有正确片段，reranker 无法创造。
2. **只在 topK 内重排没有意义**：必须扩大候选池。
3. **retrieval 后清洗收益不稳定**：导航和标题在入库时就应该去掉。
4. **15 题子集容易过度乐观**：所有策略必须看完整 60 题。
5. **7B 对上下文顺序敏感**：重排顺序变化会改变答案质量。
6. **评测裁判有波动**：单次 2.5 评分不能作为唯一决策依据。
7. **农业 KB 需要 section 语义**：预测、症状、防治措施不能用同一种召回策略。
