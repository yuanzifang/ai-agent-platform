# 农业检索召回与切块审计

日期：2026-11-03

## 1. 召回审计（Top 20）

对水稻稻瘟病、小麦叶片发黄、番茄灰霉病、苹果腐烂病、玉米高温热害等失败题，直接查知识库 913 的 Top 20：

- 相关技术资料基本都能进入 Top 20，例如：
  - 水稻稻瘟病：2024/2025 粮食作物重大病虫害防控方案
  - 苹果腐烂病：2024 苹果病虫害绿色防控方案
  - 玉米高温热害：南方防涝抗灾技术意见中的高温应对段落
- 但 Top 1/前几位经常是：
  - `中国农业农村信息网_...` 的站点导航/标题块
  - “专家预测/发生趋势/总体中等发生”类泛化预报块
  - 标题包含“怎么防治”但与当前作物无关的块（例如花生病虫害文章）

所以结论不是“标准答案完全没召回”，而是：

> **相关片段在候选里，但排序被导航块、标题块和泛化预报块压住了。**

## 2. Chunk 长度审计

知识库 913 当前：

- 总 chunk：1643
- 平均长度：约 452 字符
- 最短：28 字符
- 最长：2046 字符
- 超过 1000 字符：1 个

本地 reranker 原来 `max_length=512`，大部分 chunk 接近上限，中文 token 化后存在截断风险。现在已改为：

```text
RERANKER_MAX_LENGTH=2048
```

服务重启后健康检查正常。

## 3. 泛化片段清洗尝试

在 `AgriRetrievalPolicy` 中新增可选配置：

```json
"cleanGeneric": true
```

效果：

- 去掉首块里的农业农村信息网站点导航
- 对“怎么防治/怎么治/用药”类问题，过滤“只有趋势预测、没有防治动作”的片段
- 保留动作型技术段落

单测覆盖：

- 站点导航清洗
- 泛化趋势片段过滤
- 趋势查询保留趋势片段
- 开关关闭时保持原结果

但完整 60 题复测没有提升：

- 无清洗基线：34/60，平均分 0.7442
- 开启清洗：34/60，平均分 0.7400

因此当前 Agent 5422 保持：

```json
"cleanGeneric": false
```

清洗代码保留为可选扩展，不默认开启。

## 4. 当前结论

1. 召回不是完全失败，相关文档通常在 Top 20。
2. 主要问题是**排序污染**：导航块、标题块、趋势预报块排在技术方案前面。
3. 单纯在前端清掉导航没有稳定收益，因为：
   - 这些块通常仍包含部分正文
   - 清洗后模型上下文变化，7B 仍然可能抓住错误重点
4. 真正要解决，需要从**入库切块阶段**处理：
   - 去掉站点导航、时间、来源、字号等模板
   - 标题单独存储，不混进正文 chunk
   - 将“预测/趋势”与“防治技术”分成不同 section 类型
   - 对“怎么防治”类 query 只召回技术措施 section
5. 当前不改线上：
   - Agent 5422：V26
   - rerank=false
   - cleanGeneric=false
   - 保持可回退
