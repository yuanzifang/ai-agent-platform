# 技术决策记录

更新：2026-11-02

本文件记录会影响上线边界的技术决策；具体实现证据见对应专项文档。

## 1. 向量库 RLS：不启用

**决策：不启用 PostgreSQL RLS。**

原因：

- 当前向量库是 `schema-per-tenant`，每租户独立 Schema，没有“单表多租户行”这一 RLS 附着点。
- 表 owner 与超级用户默认绕过 RLS；为 RLS 强行改造账号模型收益很低。
- 已采用更强、可验证的边界：租户 Schema + 专用非超级用户 `aap_vector_app` + 对象所有权/GRANT。
- 若未来改为单表多租户或全局检索，再重新评估 RLS；触发条件写入 `docs/向量库RLS专项评估.md`。

**残留风险（2026-11-03 明确记录）**：当前所有租户共用一个数据库角色，应用通过
`VectorRepository.schema()` 的 `tenant_<id>` 访问隔离 Schema；该角色在数据库层
理论上可读取所有租户 Schema。隔离保证依赖应用代码、连接参数和权限校验，若出现
SQL 注入、代码缺陷或运维误操作，数据库层本身不提供第二道强制边界。
`VectorIsolationIT` 是跨租户回归测试，不是运行时约束；若威胁模型要求数据库层
强隔离，需改为每租户独立角色/连接池，或重新评估 RLS。

## 2. 全局搜索：做，不降级

**决策：保留统一全局搜索，不降级为仅模块内搜索。**

已实现：

- `GET /api/v1/search` 聚合 Agent/知识库/用例/工具。
- Jieba 中文分词、名称/描述/覆盖率相关度排序、安全高亮。
- Agent/知识库/用例/工具 InnoDB FULLTEXT（ngram）索引。
- 权限、租户、私有可见性和 ACL 过滤在聚合层保留。

## 3. 双语：继续补齐，不做一次性“全量完成”声明

**决策：前端和后端继续推进全量，但当前只声明 key parity 和已覆盖范围。**

验证结果（2026-11-02）：

```text
backend i18n: zh=86, en=86, parity OK
frontend i18n: zh-CN=2991, en-US=2991, parity OK
```

仍存在低频后端硬编码文案保留中文；这些属于后续覆盖项，不能把 key parity 当成“双语全量验收”。

## 4. 第三方渗透测试：外部依赖

**决策：本地授权预检不能替代独立第三方渗透测试。**

本地已完成越权/限流/SSRF/上传等预检；正式上线前仍需外部测试机构或具备资质的安全团队出具报告。

## 5. 文件规模

**决策：新文件硬上限 1500 行；存量超限文件冻结在 `scripts/file-size-baseline.txt`，只允许缩小。**

后续按领域拆分大文件，拆分后删除基线行，不把“刚好 2000 行以下”当作达标。

## 6. 行业能力：Agent 扩展，不进入框架核心

**决策：农业等垂直规则通过 Agent 配置启用的扩展实现，核心对话/检索不写行业分支。**

- 核心提供 `AgentRequestGuard`、`RetrievalPolicy` SPI；农业实现位于 `com.platform.extension.agri`。
- 开关落在 `agentCapabilities.extensions`、知识库绑定 `retrievalConfig` 和
  `agentCapabilities.imageUnderstandingPrompt`；迁移 `V132` 只做配置回填。
- 新增行业时优先新增扩展实现和配置，不修改 `ChatStreamService`、`HybridRetrievalService`
  等核心类。详见 `docs/Agent扩展与业务解耦.md`。

## 7. 安全默认值：单一来源

**决策：安全默认值和静态门禁清单统一放在 `backend/src/main/resources/security-defaults.json`。**

`ProductionGuard` 读取 runtime 段，`scripts/check-mvp-freeze.py` 读取 staticChecks 段；
新增默认值只改这一处，CI 与生产启动校验不会漂移。
