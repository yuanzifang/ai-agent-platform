# 镜像供应链与扫描

更新日期：2026-11-03

## 扫描范围

CI 的 `镜像构建与供应链扫描（backend/frontend/alert-relay）` job 会构建并扫描：

- `aap/backend:ci`
- `aap/frontend:ci`
- `aap/alert-relay:ci`

每个镜像同时产出 Trivy HIGH/CRITICAL 漏洞报告和 CycloneDX SBOM；Release 工作流对
发布镜像重复扫描，并把后端/前端/告警中继镜像 SBOM 与依赖 SBOM 合并、校验、签名后
附加到 Release。

## 固定标签与 digest

`docker-compose.yml` 不再使用 `:latest`，默认固定版本 + 多架构 index digest：

- MinIO：`quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z@sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e`
- Ollama：`ollama/ollama:0.40.7@sha256:2e6cc92ffa43b4b1a2e70e315407e00ac97ec125afc71277d73c7efe01c4f31b`

生产/发布环境可通过 `.env` 指向自建镜像仓库中**同一 digest** 的镜像：

```dotenv
MINIO_IMAGE=<registry>/minio/minio:RELEASE.2025-09-07T16-13-09Z@sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e
OLLAMA_IMAGE=<registry>/ollama/ollama:0.40.7@sha256:2e6cc92ffa43b4b1a2e70e315407e00ac97ec125afc71277d73c7efe01c4f31b
```

`scripts/check-mvp-freeze.py` 会阻断 `docker-compose.yml` 重新出现 `:latest`。

## 运行

```bash
python3 scripts/check-mvp-freeze.py
docker-compose config
```

CI 默认对 HIGH/CRITICAL 采用观察模式（失败不阻断），但报告和 SBOM 必须上传；需要
强制阻断时，将对应 Trivy 步骤的 `exit-code` 改为 `1`，并按 `.trivyignore` 维护
已评估例外。

## 2026-11-03 扫描收敛结果

- 初始（v0.3.11）：
  - backend：28 个（HIGH 17 / CRITICAL 11）
  - frontend：60 个（HIGH 57 / CRITICAL 3）
  - alert-relay：10 个 HIGH
- 升级运行时镜像、移除运行时 npm、升级 Netty/Tomcat/Jackson/Guava/BouncyCastle/Snappy/Spring AI 后：
  - frontend：**0 HIGH/CRITICAL**
  - alert-relay：**0 HIGH/CRITICAL**
  - backend：**4 CRITICAL + 1 HIGH**，均为已识别残留：
    - Spring Framework 6.2.19 的 WebFlux/WebMVC CVE，当前 Boot 3.5 线无 6.x 修复版本
    - `lark-mcp` 依赖的 `basic-ftp` 5.3.1
- CI/Release 已对三个镜像启用 HIGH/CRITICAL 阻断；backend 的 Spring 6.2.19 与 lark-mcp/basic-ftp 残留通过 `.trivyignore` 逐条 VEX 说明豁免，并在文档中保留复查条件。
