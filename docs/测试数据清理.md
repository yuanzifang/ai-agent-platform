# E2E 测试数据清理

E2E 会创建临时 Agent、Provider 和模型。Agent 有删除接口，Provider/模型目前没有暴露删除接口，因此分两步处理：

## 1. Agent 清理

先 dry-run：

```bash
python3 scripts/cleanup-e2e-data.py
```

脚本只匹配以下名称前缀：

```text
E2E...
LOCAL-SMOKE-...
LOCAL-REWRITE-...
```

确认打印结果后执行：

```bash
python3 scripts/cleanup-e2e-data.py --apply
```

会先删除工作流，再删除 Agent。演示 Agent `4878`、`1`、`2`、`3` 不匹配这些前缀，不会被删除。

## 2. Provider / 模型清理

已支持可选自动清理；默认仍然只报告：

```bash
# 只 dry-run
python3 scripts/cleanup-e2e-data.py

# 删除 E2E Agent
python3 scripts/cleanup-e2e-data.py --apply

# 同时清理 E2E Provider / 临时模型
MYSQL_PASSWORD=*** python3 scripts/cleanup-e2e-data.py --apply --apply-providers
```

自动清理只匹配：

- Provider 名称严格以 `E2E ` 开头
- 模型名称为 `broken-model-*` 或 `claude-mock`
- 模型挂在 `E2E ` Provider 下

执行前会检查未删除 Agent 是否仍引用临时模型；有引用则中止。数据库密码只从 `MYSQL_PASSWORD` 环境变量读取，不写入命令行参数。

如不使用脚本，也可人工执行以下 SQL。执行前必须确认没有线上 Agent 引用这些模型。

```sql
START TRANSACTION;

DELETE FROM model
WHERE model_name LIKE 'broken-model-%' OR model_name = 'claude-mock';

DELETE FROM model
WHERE provider_id IN (SELECT id FROM provider WHERE name LIKE 'E2E %');

DELETE FROM provider_credential
WHERE provider_id IN (SELECT id FROM provider WHERE name LIKE 'E2E %');

DELETE FROM provider
WHERE name LIKE 'E2E %';

COMMIT;
```

执行后检查：

```sql
SELECT COUNT(*) FROM provider WHERE name LIKE 'E2E %';
SELECT COUNT(*) FROM model WHERE model_name LIKE 'broken-model-%' OR model_name = 'claude-mock';
```

## 清理后的基线

```text
Agent: 4（含演示 Agent 4878）
Provider: 2（DeepSeek、本机 Ollama）
临时 E2E Provider: 0
临时 E2E 模型: 0
```

## 注意

- 不要使用 `DELETE FROM model` 全表清理，生产模型和本地 CHAT 模型（`qwen2.5:7b-chat`）必须保留。
- 执行 SQL 前先备份数据库。
- 不要清理 `provider.id=1` 的 DeepSeek 和 `provider.id=86` 的本机 Ollama。
- E2E 测试复用数据库时，建议每轮结束后至少执行一次 Agent dry-run 检查。
