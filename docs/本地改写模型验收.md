# 本地改写模型验收

目标：验证 REWRITE 步骤可以完全在本机模型上执行，不把 query/context/answer 发送到外部服务。

## 环境

- 机器：Apple M4 Max / 128GB
- Ollama：`0.24.0`
- 本地模型：`qwen2.5:7b`（4.7GB）
- Provider：`本地 Ollama`，`base_url=http://127.0.0.1:11434`
- 平台模型：`qwen2.5:7b`，用途 `PLATFORM`，状态 `ENABLED`

说明：模型权重和平台数据库记录不进入代码仓库；换机器需要先安装 Ollama、拉取模型，并在「模型接入」登记同一个模型名。

## 启动与登记

一键安装并登记平台专用模型：

```bash
python3 scripts/setup-local-eval-model.py --model qwen2.5:7b
```

脚本会检查/拉取 Ollama 模型、登录平台、找到 Ollama Provider，并以 `PLATFORM` 用途登记；已有记录会复用。

手工确认：

```bash
ollama list | grep qwen2.5
curl -s http://127.0.0.1:11434/api/tags
```

## 验收命令

```bash
cd frontend
E2E_LOCAL_REWRITE=1 \
E2E_LOCAL_REWRITE_MODEL=qwen2.5:7b \
./node_modules/.bin/playwright test e2e/eval-step.spec.ts:100 --reporter=list
```

测试会：

1. 登录平台；
2. 调用 `POST /api/v1/eval/steps/run`；
3. 使用 `stepConfig.model=qwen2.5:7b`；
4. 校验 `must_keep=["退款","慢"]`、得分 ≥ 0.8、`passed=true`；
5. 打印实际改写文本。

## 验收结果

```text
LOCAL-REWRITE model=qwen2.5:7b score=1
actual=用户反馈退款速度慢，请帮忙处理
1 passed (1.8s)
```

查询数据全程只到 `127.0.0.1:11434`，未经过外部 API。

2026-10-29 本机复测（8080 + dev 租户）：

```text
LOCAL-REWRITE model=qwen2.5:7b score=1 actual=用户反映退款速度慢，请帮忙处理
1 passed (1.6s)
```

后端路由日志确认 `provider=本地 Ollama(OLLAMA) base=http://127.0.0.1:11434 model=qwen2.5:7b`；本次成功的本地验收请求未使用云端模型。

REWRITE 的显式模型现在走 `ChatModelRouter.resolveStrict`：模型未登记或租户上下文不匹配时返回 400，不会静默回落到默认云端模型。

之前也用 `qwen3.6:27b` 验证通过，但冷启动约 2.5 分钟、热调用仍较慢，不建议作为改写默认模型。`qwen2.5:7b` 更适合本地回归。

## 平台模型与 Agent 模型边界

- 本地聊天模型在 `model.purpose` 中标记为 `PLATFORM`，Agent/裁判的 `CHAT` 模型下拉不会出现它，也不会成为默认聊天模型。
- Agent 创建/编辑时后端校验 `modelConfig.modelName/fallbackModelName`：若指向 `PLATFORM` 模型直接拒绝。
- Agent 任务的 REWRITE 步骤优先使用该 Agent 的 `modelConfig.modelName`；步骤样本里的 `model` 不会覆盖它。
- 只有平台单步试跑（没有 Agent 上下文）或显式平台评测配置才使用本地模型。
- 门禁裁判默认 `deepseek-flash`；可在系统设置把 `eval.gate-judge-model` 改为 `qwen2.5:7b`，无需重启。
- 评测中心“裁判模型”下拉允许选择 `CHAT` 和 `PLATFORM` 模型；Agent 模型下拉仍只允许 `CHAT`。

## 真实裁判门禁

后端启动时指定：

```bash
--eval.gate-judge-model=qwen2.5:7b
```

然后用真实 Agent 模型跑门禁用例：

```bash
E2E_REAL_MODEL=1 E2E_API_BASE=http://127.0.0.1:8081/api/v1 \
./node_modules/.bin/playwright test e2e/eval-real-gate.spec.ts --reporter=list
```

验收结果：真实 DeepSeek Agent 回答 + 本地 qwen 裁判，裁判理由为“回答偏离提问要求”，门禁因 RETRIEVAL 失败阻断。

## 与规则 fallback 的关系

- `stepConfig.localOnly=true` / `mode=local`：确定性规则，无需模型，秒级。
- `stepConfig.model=qwen2.5:7b`：真实本地模型，语义改写质量更好，但仍需人工抽检。
- 发布门禁/回归默认不自动选本地模型；由步骤配置显式指定，避免不同机器模型缺失导致任务失败。
- Agent 评测/门禁中的 ANSWER 仍使用 Agent 自己的模型；REWRITE 也按 Agent 模型优先，本地模型只用于平台侧。
