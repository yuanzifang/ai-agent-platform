# 思考模式（Thinking）与模型思考级别

不同模型对「思考 / 推理」的支持方式不同，所以能力声明放在**模型**上，Agent 只在能力范围内开关。

## 1. 模型级能力（「模型接入 → 配置」）

`model.capabilities` JSON：

```json
{
  "multimodal": true,
  "functionCall": true,
  "reasoning": true,
  "reasoningParam": "effort",          // effort | budget
  "reasoningLevels": ["low", "medium", "high"]
}
```

`model.default_params` 可带默认级别：

```json
{ "temperature": 0.7, "reasoningEffort": "medium" }
```

- `reasoning=false`（默认）：该模型下的 Agent 无法开启思考，UI 开关不可用
- `reasoningParam`：
  - `effort` → OpenAI 兼容协议传 `reasoning_effort`
  - `budget` → Anthropic 原生协议传 `thinking.budget_tokens`（缺省时 Anthropic Provider 自动按 budget）
- `reasoningLevels`：该模型实际支持的级别，Agent 编辑页只列这些（为空则默认 low/medium/high）

接口：`PUT /api/v1/models/{id}`，可只传变化项，服务端会合并 JSON、保留其它能力键：

```json
{ "reasoning": true, "reasoningParam": "effort",
  "reasoningLevels": ["low","medium","high"], "defaultReasoningEffort": "medium" }
```

> 模型同步（`/provider/{id}/models/sync`）只刷新 `multimodal`，不会覆盖管理员配的思考能力。
> 新同步/新建的模型默认 `reasoning=false`，需要显式开启。

## 2. Agent 级配置（Agent 编辑 → 模型选择）

`agent.model_config` 增加两个字段：

```json
{
  "modelName": "deepseek-flash",
  "fallbackModelName": null,
  "temperature": 0.7,
  "thinking": true,
  "reasoningEffort": "high"
}
```

- 只有选中模型的 `capabilities.reasoning=true` 时开关可用；换模型会自动收敛级别
- 开启思考后温度滑杆禁用（推理模型普遍不接受自定义 temperature）
- 保存/发布/版本快照都会带上这两个字段

## 3. 后端映射（`ChatModelRouter.options`）

| Provider | 思考开启 | 关闭 |
| --- | --- | --- |
| Anthropic 原生 | `thinking(ENABLED, budget)`；级别→budget：minimal 1k / low 2k / medium 4k / high 8k；`max_tokens = budget + 4k` | 4096 + temperature |
| Gemini（OpenAI 兼容） | base 填 `https://generativelanguage.googleapis.com/v1beta/openai`，路径自动用 `/chat/completions` | 同 OpenAI 兼容 |
| OpenAI 兼容 | `reasoning_effort = level` | temperature |

- 级别统一收敛为 `minimal / low / medium / high`，未知值按 `medium`
- 请求级别不在模型 `reasoningLevels` 内时，回落到模型默认级别/medium
- 模型未声明 `reasoning=true` 时忽略 Agent 的 thinking 配置（不会把不支持的参数发给 Provider）
- 流式对话、非流式、调试对话、子 Agent 调用四条链路都走同一套映射

单测：`backend/src/test/java/com/platform/model/service/ChatModelRouterReasoningTest.java`（7 个用例）。

## 4. 已知边界

- 是否真正“思考”取决于模型服务端；平台只负责按能力声明下发参数
- 思考过程（`reasoning_content`）暂未在对话气泡里单独展示，只有 usage 里的 reasoning tokens 会计费/统计
