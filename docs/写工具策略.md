# 写工具细粒度策略

## Agent 配置

`agentCapabilities`：

```json
{
  "functionCall": true,
  "writeToolPolicy": "ALLOWLIST",
  "allowedWriteToolIds": [12, 15],
  "writeToolMaxArgs": 16384,
  "writeToolArgRules": {
    "12": ["orderId", "reason"]
  },
  "writeToolArgPatterns": {
    "12": {"orderId": "^[A-Z0-9-]{6,32}$"}
  },
  "writeToolAmountLimits": {
    "12": {"amount": 1000}
  }
}
```

- `writeToolPolicy`：
  - `ALLOW_ALL`：消息显式允许写操作时全部放行（默认，兼容旧行为）；
  - `BLOCK`：即使消息显式允许也阻断；
  - `APPROVAL`：写工具只创建“逐次审批”记录，不执行；审批箱批准后由平台执行一次，拒绝则不执行；
  - `ALLOWLIST`：仅 `allowedWriteToolIds` 中的工具可执行。
- `writeToolMaxArgs`：模型传入参数 JSON 最大字节数，默认 16384。
- `writeToolArgRules`：按工具限制参数名白名单；出现未授权参数即阻断。
- `writeToolArgPatterns`：按工具/参数配置正则，值必须完整匹配；非法正则按阻断处理。
- `writeToolAmountLimits`：按工具/参数配置数值上限；无法解析或超过上限按阻断处理。
- 消息级 `allowWriteTools` 仍是第一道人确权；Agent 策略只收窄、不放大权限。
- 技能脚本仍只受消息级 `allowWriteTools` 控制。
- 显式允许写操作时会写审计：`tool.write.confirm`（记录 Agent/会话/输入摘要）。
- 若工具被 DENIED，即使模型仍生成了“已完成”措辞，最终回答会追加安全提示，明确实际未执行。

## 已验证

- E2E：
  - 默认阻断；
  - 消息显式允许后执行；
  - `BLOCK` 即使允许也阻断；
  - `ALLOWLIST` 命中后执行；
  - 审计存在 `tool.write.confirm`。

## 已验证

- `ToolPolicyTest` 覆盖参数白名单、字段正则、金额上限和非法配置 fail-closed。
- E2E 覆盖默认阻断、显式允许、`BLOCK`、`ALLOWLIST` 和 `tool.write.confirm` 审计。

## 逐次审批

- 待审批记录表：`tool_approval`（V98）
- 查询：`GET /api/v1/tool-approvals?status=PENDING`
- 决策：`POST /api/v1/tool-approvals/{id}/decide` `{"approve":true,"comment":"..."}`
- 批准后由平台调用工具一次；拒绝/执行失败都会落状态
- 审批箱页面新增「写工具逐次审批」表格
- 实测：创建审批 → 批准 → 计算器执行 `6*7` 返回 `42.0`
- 审批超时：默认 1440 分钟（`tool.approval.timeout-minutes`），定时扫描置为 `EXPIRED`；管理接口 `POST /tool-approvals/expire-scan` 可手动触发。

技能脚本审批：

- `APPROVAL` 策略同样作用于技能脚本；
- 批准后由平台执行一次脚本（Python/JavaScript）；实测返回 `skill-approval-ok`；
- 审批记录 `tool_type=SKILL`，执行入口与普通工具分开。

仍缺：

- 策略变更历史/发布门禁。
