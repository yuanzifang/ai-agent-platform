# 本机 API 性能基线

日期：2026-10-24（ab）/ 2026-10-25（k6 SSE）/ 2026-10-27（30 分钟 SSE、RAG/审核）  
环境：本机 macOS、后端单实例、MySQL/Redis 本机、数据量为开发基线（3 Agent、13 会话、96 消息）。  
工具：ApacheBench（`ab`），200 请求、20 并发、GET、租户限流临时放开；k6 2.3.0 SSE 首 Token 基线。  
结论：**这是基线观测，不是上线压测验收**；已补 30 分钟 mock SSE 长稳和 10 分钟 RAG/审核链路长稳，但真实模型首 Token、真实模型 RAG/审核 30 分钟、100+ 真实模型并发仍未覆盖。

## k6 SSE 首 Token 基线（2026-10-25）

环境：本机后端单实例、mock DeepSeek 上游、k6 2.3.0；临时放开租户限流。  
场景：`constant-arrival-rate`，3 req/s、持续 30s、10 预分配 VU；每轮创建会话并发送流式消息，等待 `done` 事件。

| 指标 | 结果 |
|---|---:|
| 对话迭代 | 90 |
| HTTP 请求 | 104 |
| 失败率 | 0% |
| 校验通过率 | 100% |
| 首 Token 平均 | 28.2 ms |
| 首 Token p95 | 50.7 ms |
| 整轮平均 | 53.5 ms |
| 整轮 p95 | 85.0 ms |

说明：mock 模型只验证平台 SSE/会话/鉴权链路，**不能代表真实模型首 Token 时延**。脚本为 `scripts/perf-k6.js`。

## k6 SSE 首 Token（2026-10-25）

- 工具：k6 2.3.0，脚本 `scripts/perf-k6.js`
- 场景：constant-arrival-rate，3 req/s，30 秒，90 次流式对话
- 上游：本机 mock OpenAI 兼容服务（非真实 DeepSeek）
- 每次对话：创建会话 → `POST /conversations/{id}/messages`，`stream=true`
- 指标：
  - 首 Token（`chat_ttfb_ms`）：平均 **28.2ms**，p95 **50.7ms**
  - 整轮 SSE（`chat_total_ms`）：平均 **53.5ms**，p95 **85.0ms**
  - 成功率：**100%**
  - `http_req_failed`：**0**
  - 总请求：104（含登录/建会话）
- 结论：仅证明本地 SSE 基础链路在 3 req/s/30s 下无失败；**不能证明真实模型、长稳或 100+ 并发**。

## 复现

```bash
# 临时放开租户限流，避免 429 干扰
mysql -uroot -proot ai_agent_platform -e \
  "UPDATE sys_tenant_quota SET max_api_calls_per_min=100000;"
./scripts/perf-baseline.sh
# k6 SSE（mock 模型；真实模型需替换 Provider）
PERF_RATE=3 PERF_DURATION=30s k6 run scripts/perf-k6.js
# RAG + 审核事件（需先通过 API 创建/解析知识库，并把 ID 传入；
# PERF_MODEL 指向 mock Provider 的模型，perf-rag-mock 为本次临时测试模型）
PERF_RATE=3 PERF_DURATION=10m PERF_MODEL=perf-rag-mock \
  PERF_KB_ID=390 PERF_MESSAGE='退款政策是什么？请简短回答。转账' \
  PERF_WARN_WORD='转账' k6 run scripts/perf-k6.js
mysql -uroot -proot ai_agent_platform -e \
  "UPDATE sys_tenant_quota SET max_api_calls_per_min=60;"
```

## k6 SSE 首 Token（2026-10-25）

- 工具：k6 2.3.0，`scripts/perf-k6.js`；
- 上游：本机 OpenAI 兼容 mock（DeepSeek Provider 指向 mock），非真实模型；
- 场景：`constant-arrival-rate` 3 req/s，持续 30s，10 预分配 VU；每轮创建会话并发送 `stream=true` 消息，等待 `event:done`；
- 结果：90 次对话、104 个 HTTP 请求，`http_req_failed=0`、校验通过率 100%；
- 首 Token：avg **28.2ms**、p95 **50.7ms**；
- 整轮：avg **53.5ms**、p95 **85.0ms**。

**结论：** 验证了登录 → 建会话 → SSE 鉴权/流式/结束事件的并发链路；mock 上游不代表真实模型首 Token，也未覆盖真实模型 30 分钟长稳、100+ 并发、RAG/审核真实模型开销，不能作为上线验收依据。


## 2026-10-26 100 并发 API 基线

环境：本机单后端、100 并发、1000 请求/接口、租户限流临时放开；仍是开发数据量，不是生产验收。

| 接口 | QPS | 平均 ms | p50 ms | p95 ms | p99 ms | 失败 |
|---|---:|---:|---:|---:|---:|---:|
| `/api/v1/agent` | 3168.57 | 31.560 | 28 | 53 | 59 | 0 |
| `/api/v1/knowledge-base` | 1974.35 | 50.650 | 47 | 79 | 90 | 0 |
| `/api/v1/observability/overview` | 183.42 | 545.193 | 528 | 588 | 632 | 0 |

## 30 分钟 SSE 长稳（2026-10-27，mock）

环境：本机独立后端（18081）、本机 mock OpenAI 兼容上游、MySQL/Redis 本机；k6 2.3.0。  
场景：3 req/s 持续 **30 分钟**，每轮创建会话并等待 SSE `done`。

| 指标 | 结果 |
|---|---:|
| 完成迭代 | 5,400 |
| chat_ok | **99.96%**（2 次未收到 done） |
| HTTP 请求失败 | **0.055%**（3/5,415） |
| 首 Token avg / p95 | 40.43ms / 48.69ms |
| 整轮 avg / p95 | 59.08ms / 69.10ms |

k6 阈值通过（`chat_ok>0.99`、`http_req_failed<0.01`）。

**边界：仍是 mock 模型**；验证了平台 30 分钟 SSE/会话/鉴权/数据库读写稳定性，不代表真实模型首 Token、RAG/审核全链路或 100+ 长稳。第一次真实 DeepSeek 长跑因环境重启产生 1.3% 失败，未计入本结果。

## RAG/审核链路 10 分钟（2026-10-27，mock）

环境：本机独立后端（18083）、专用 mock OpenAI 兼容 Provider/Model、MySQL/Redis/PgVector/MinIO 本机、Ollama `bge-m3` embedding；k6 2.3.0。  
场景：1 个退款政策知识库（1 文档/1 chunk），每轮绑定知识库的 Agent 以 3 req/s 持续 **10 分钟** 发送“退款政策是什么？请简短回答。转账”，同时验证 `citation` 与审核 `moderation` 事件。

| 指标 | 结果 |
|---|---:|
| 完成迭代 | 1,801 |
| chat_ok | **99.94%**（1 次未收到 done） |
| HTTP 请求失败 | **0.055%**（1/1,815） |
| RAG citation 事件 | **99.94%** |
| 审核 moderation 事件 | **99.94%** |
| 首 Token avg / p95 | 203.97ms / 257.93ms |
| 整轮 avg / p95 | 235.40ms / 312.48ms |

k6 阈值通过（`chat_ok>0.99`、`rag_citation>0.99`、`moderation_warn>0.99`）。

**边界：** mock 模型 + 单个小知识库，验证的是“检索注入 → 审核事件 → SSE 完成”的平台链路稳定性，不代表真实模型质量、真实大知识库检索时延或 30 分钟 RAG 长稳。脚本新增 `PERF_MODEL/PERF_KB_ID/PERF_MESSAGE/PERF_WARN_WORD` 可选参数，默认行为不变。
