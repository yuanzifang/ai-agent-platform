# 工作流示例：本地模型意图分类客服

本地 Agent：

```text
Agent ID: 4878
名称：本地意图客服（本地模型）
状态：PUBLISHED
默认模型：qwen2.5:7b-chat（本机 Ollama 对话别名）
工作流：本地意图分类客服工作流 V2，17 个节点
工作流 LLM 节点：8 个，全部 qwen2.5:7b（本机 Ollama，不使用 Mock）
```

Agent 默认模型已切到本地 `qwen2.5:7b-chat`，工作流所有 LLM 节点显式使用 `qwen2.5:7b`，两条链路都不依赖云端模型。

分类链路已收敛为一次意图识别 + 共享状态条件路由，不再串行调用 4 次 YES/NO 判断；本地全分支 E2E 从约 21.5s 降到约 9.4s。

本地默认模型可通过以下脚本重复配置：

```bash
python3 scripts/setup-local-agent-model.py --agent-id 4878
```

脚本会创建本机 `qwen2.5:7b-chat` alias、登记为 CHAT 模型、切换 Agent 默认模型并移除云端 fallback。

## 图结构

```text
START
  → 意图识别（LLM，一次分类：订单 / 售后退款 / 咨询 / 投诉 / 其他）
  → 保存意图（STATE intent）
  → 是否订单（CONDITION，读取 state.intent）
      true  → 订单回复 → END
      false → 是否售后退款
  → 是否售后退款（CONDITION，读取 state.intent）
      true  → 退款安抚解释
              → 沟通是否不通过（LLM：PASS/FAIL）
                  FAIL → 退款人工审核（APPROVAL）
                          → 通过后 → 退款最终回复 → END
                  PASS → 退款最终回复 → END
      false → 是否投诉
  → 是否投诉（CONDITION，读取 state.intent）
      true  → 投诉回复 → END
      false → 是否咨询
  → 是否咨询（CONDITION，读取 state.intent）
      true  → 咨询回复 → END
      false → 其他回复 → END
```

## 分支用例矩阵

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 订单 | 我的订单什么时候发货？ | 订单回复，SUCCESS |
| 售后退款 PASS | 请问退款一般多久到账？ | 退款安抚解释 → 退款最终回复，SUCCESS |
| 售后退款 FAIL | 我要申请退款，退款太慢了，我要投诉你们 | 退款安抚解释 → 退款人工审核，WAITING_APPROVAL |
| 审批通过 | 对退款 FAIL 的审批执行 approve | 继续退款最终回复，SUCCESS |
| 审批拒绝 | 对退款 FAIL 的审批执行 reject | 运行结束为 REJECTED |
| 投诉 | 我要投诉你们的服务态度 | 投诉回复，SUCCESS |
| 咨询 | 你们这个产品怎么使用？ | 咨询回复，SUCCESS |
| 其他 | 今天天气怎么样？ | 其他回复，SUCCESS |

同时覆盖条件节点的 true/false 分支：订单、售后退款、投诉、咨询、退款沟通失败判断。前四个条件读取共享状态 `intent`，最后一个是判断退款沟通 LLM 的上一节点输出。

## 设计注意

- 画布测试运行使用当前草稿（`draft=true`），正式调用使用已发布版本。
- 分类只调用一次 LLM，条件节点按 `state.intent` 路由，避免多次串行模型调用。
- CONDITION 支持判断来源：`last`（上一节点输出）、`state`（共享状态）、`input`（用户输入）。
- CONDITION 只负责路由，输出保留前序节点内容，避免审批页只显示 `true/false`。
- 条件节点使用 T/F 双端口，普通节点拖线直接更新 `next`。
- 本地模型调用日志应出现 `provider=本地 Ollama`、`model=qwen2.5:7b` 或 `model=qwen2.5:7b-chat`。
- Agent 默认模型使用本地 CHAT alias，工作流节点使用本地 PLATFORM 模型；两者都通过本机 Ollama 路由。
