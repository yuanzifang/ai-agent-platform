# 工作流示例：本地模型意图分类客服

本地 Agent：

```text
Agent ID: 4809
名称：本地意图客服-<时间戳>
模型节点：qwen2.5:7b（本机 Ollama，不使用 Mock）
```

## 图结构

```text
START
  → 意图识别（LLM）
  → 保存意图（STATE intent）
  → 订单判断（LLM：YES/NO）
      YES → 订单回复 → END
      NO  → 售后退款判断
  → 售后退款判断（LLM：YES/NO）
      YES → 退款安抚解释
              → 沟通是否不通过（LLM：PASS/FAIL）
                  FAIL → 退款人工审核（APPROVAL）
                          → 通过后 → 退款最终回复 → END
                  PASS → 退款最终回复 → END
      NO  → 投诉判断
  → 投诉判断（LLM：YES/NO）
      YES → 投诉回复 → END
      NO  → 咨询判断
  → 咨询判断（LLM：YES/NO）
      YES → 咨询回复 → END
      NO  → 其他回复 → END
```

## 分类

- 订单：下单、物流、发货、订单状态
- 售后退款：退款、退货、售后、退款进度
- 咨询：产品功能、使用方法、政策说明
- 投诉：不满、服务态度、要求投诉、强烈负面情绪
- 其他：以上都不是

## 本地测试结果

输入示例：

```text
我的订单什么时候发货？
→ SUCCESS：订单回复
```

```text
我要申请退款，退款太慢了，我要投诉你们
→ WAITING_APPROVAL：退款人工审核
```

```text
我要投诉你们的服务态度
→ SUCCESS：投诉回复
```

```text
你们这个产品怎么使用？
→ SUCCESS：咨询回复
```

```text
今天天气怎么样？
→ SUCCESS：其他回复
```

退款审核通过后会继续执行“退款最终回复”，不会停在审批节点。

## 设计注意

- 画布测试运行使用当前草稿（`draft=true`），正式调用使用已发布版本。
- CONDITION 只负责路由，输出保留前序节点内容，避免审批页只显示 `true/false`。
- 条件节点使用 T/F 双端口，普通节点拖线直接更新 `next`。
- 本地模型调用日志应出现 `provider=本地 Ollama`、`model=qwen2.5:7b`。
