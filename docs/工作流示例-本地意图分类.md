# 工作流示例：本地模型意图分类客服

本地 Agent：

```text
Agent ID: 4878
名称：本地意图客服（本地模型）
状态：PUBLISHED
工作流：本地意图分类客服工作流 V1，21 个节点
模型节点：qwen2.5:7b（本机 Ollama，不使用 Mock）
```

Agent 默认模型仍是 `deepseek-flash`，但本工作流所有 LLM 节点都显式配置为 `qwen2.5:7b`，运行不依赖云端模型。

## 图结构

```text
START
  → 意图识别（LLM）
  → 保存意图（STATE intent）
  → 订单判断（LLM：YES/NO）
      YES → 订单回复 → END
      NO  → 售后退款判断
  → 售后退款判断（LLM：YES/NO）
      YES → 退款安抚解释
              → 沟通是否不通过（LLM：PASS/FAIL）
                  FAIL → 退款人工审核（APPROVAL）
                          → 通过后 → 退款最终回复 → END
                  PASS → 退款最终回复 → END
      NO  → 投诉判断
  → 投诉判断（LLM：YES/NO）
      YES → 投诉回复 → END
      NO  → 咨询判断
  → 咨询判断（LLM：YES/NO）
      YES → 咨询回复 → END
      NO  → 其他回复 → END
```

## 分支用例矩阵

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 订单 | 我的订单什么时候发货？ | 订单回复，SUCCESS |
| 售后退款 PASS | 请问退款一般多久到账？ | 退款安抚解释 → 退款最终回复，SUCCESS |
| 售后退款 FAIL | 我要申请退款，退款太慢了，我要投诉你们 | 退款安抚解释 → 退款人工审核，WAITING_APPROVAL |
| 审批通过 | 对退款 FAIL 的审批执行 approve | 继续退款最终回复，SUCCESS |
| 审批拒绝 | 对退款 FAIL 的审批执行 reject | 运行结束为 REJECTED |
| 投诉 | 我要投诉你们的服务态度 | 投诉回复，SUCCESS |
| 咨询 | 你们这个产品怎么使用？ | 咨询回复，SUCCESS |
| 其他 | 今天天气怎么样？ | 其他回复，SUCCESS |

同时覆盖条件节点的 true/false 分支：订单判断、售后退款判断、投诉判断、咨询判断、退款沟通失败判断。

## 自动化测试

### 全分支本地模型 E2E

文件：

```text
frontend/e2e/workflow-all-cases.spec.ts
```

该测试读取：

```text
frontend/e2e/fixtures/local-intent-workflow.json
```

覆盖：

- 五类意图
- 退款 PASS / FAIL
- 审批通过 → 退款最终回复
- 审批拒绝
- 所有 LLM 节点必须使用 `qwen2.5:7b`
- 使用真实本机 Ollama，不使用 Mock

本地执行：

```bash
cd frontend
E2E_LOCAL_WORKFLOW=1 ./node_modules/.bin/playwright test e2e/workflow-all-cases.spec.ts
```

默认 E2E 会跳过该用例，避免没有本地 Ollama 的 CI 环境误跑。

### 画布交互 E2E

文件：

## 本地手工验证结果

```text
我的订单什么时候发货？
→ SUCCESS：订单回复
```

```text
请问退款一般多久到账？
→ SUCCESS：退款最终回复
```

```text
我要申请退款，退款太慢了，我要投诉你们
→ WAITING_APPROVAL：退款人工审核
```

```text
我要投诉你们的服务态度
→ SUCCESS：投诉回复
```

```text
你们这个产品怎么使用？
→ SUCCESS：咨询回复
```

```text
今天天气怎么样？
→ SUCCESS：其他回复
```

退款审核通过后会继续执行“退款最终回复”，不会停在审批节点；审批拒绝会结束为 `REJECTED`。

## 设计注意

- 画布测试运行使用当前草稿（`draft=true`），正式调用使用已发布版本。
- CONDITION 只负责路由，输出保留前序节点内容，避免审批页只显示 `true/false`。
- 条件节点使用 T/F 双端口，普通节点拖线直接更新 `next`。
- 本地模型调用日志应出现 `provider=本地 Ollama`、`model=qwen2.5:7b`。
