# 工具调用入参校验

更新：2026-10-27

## 目标

工具执行前由平台校验参数，不能只依赖模型遵守 `inputSchema`。校验失败时，平台把**结构化错误作为 tool result 回给模型**，让模型有机会修正参数并重新发起工具调用；达到重试上限后才停止自动重试。

## 流程

```text
模型 tool call
  → 解析 JSON object
  → JSON Schema 校验（required/type/enum/range/pattern/长度/额外字段/嵌套）
  → 校验失败：返回 retryable=true 的结构化 tool result，不执行下游
  → 模型修正参数并重试（最多 N 次）
  → 校验通过：写工具策略/审批 → 执行
```

写工具必须先完成入参校验，再创建审批或执行下游，避免审批单绑定非法参数。

## 错误返回示例

```json
{
  "ok": false,
  "error": "INVALID_ARGUMENTS",
  "retryable": true,
  "attempt": 1,
  "maxAttempts": 3,
  "violations": [
    {"path": "$.amount", "rule": "type", "expected": "integer", "actual": "string"},
    {"path": "$.currency", "rule": "enum", "expected": "[\"CNY\",\"USD\"]", "actual": "string"}
  ],
  "message": "参数校验失败，请根据 violations 修正后重试"
}
```

达到上限后返回 `retryable=false`，工具不执行，模型应向用户说明参数问题。

## 覆盖范围

- API 工具
- MCP 工具（使用工具声明的 inputSchema 本地预校验）
- 技能脚本工具（默认值合并后校验）
- 内置工具 `calculator` / `current_time`
- 子 Agent 工具

## 支持的 Schema 子集

- `type`、`required`、`properties`、`additionalProperties`
- `enum`、`const`
- `minLength`、`maxLength`、`pattern`
- `minimum`、`maximum`、`exclusiveMinimum`、`exclusiveMaximum`
- `minItems`、`maxItems`、`items`
- `minProperties`、`maxProperties`
- `allOf`、`anyOf`、`oneOf`
- `format`：`email`、`uuid`、`date`、`date-time`、`uri`
- 本地 `#/...` 引用（如 `#/$defs/...`）

远程/外部 `$ref`、递归引用等复杂关键字仍不解释；工具自身、远程 MCP Server 或后续 Schema 引擎仍需兜底。

## 配置

Agent 编辑页「能力」可配置：

- `入参校验重试次数`：1–20，默认 3

环境变量仅作为全局兜底：

```yaml
tool:
  input-validation:
    max-attempts: ${TOOL_INPUT_VALIDATION_MAX_ATTEMPTS:3}
```

Agent 的 `agentCapabilities.maxInputValidationAttempts` 优先于全局配置。`max-attempts` 包含首次校验。

## 不可重试情况

- 工具不存在/未启用
- 权限、审批或写工具策略阻断
- SSRF/网络策略阻断
- 已执行并产生副作用的失败

这些不应通过重复调用工具来绕过；平台返回明确的最终错误。
