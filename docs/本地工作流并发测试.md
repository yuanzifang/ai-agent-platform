# 本地工作流并发测试

日期：2026-10-31

## 目标

验证 Agent `4878` 的发布版工作流在本机 Ollama `qwen2.5:7b` 下的并发稳定性，不使用 Mock，也不调用云端 Provider。

测试分支：订单问题，固定经过：

```text
开始 → 意图识别 → 保存意图 → 是否订单 → 订单回复
```

每轮 2 次本地模型调用。

## 脚本

```text
scripts/local-workflow-concurrency.py
```

执行：

```bash
python3 scripts/local-workflow-concurrency.py --runs 8 --concurrency 4
python3 scripts/local-workflow-concurrency.py --runs 16 --concurrency 8
```

## 实测结果

### 4 并发 / 8 轮

```text
success=8/8
wall=2239ms
p50=890ms
p95=1520ms
max=1520ms
```

### 8 并发 / 16 轮

```text
success=16/16
wall=2858ms
p50=1373ms
p95=1395ms
max=1461ms
```

所有请求均完成完整节点链路：

```text
开始 → 意图识别 → 保存意图 → 是否订单 → 订单回复
```

## 结论

- 当前本机 Ollama 单模型在 8 并发下未出现失败或超时。
- P95 约 1.4s，主要由本地模型推理和 Ollama 排队决定。
- 这是单机开发环境结果，不等同于生产容量；生产需要独立机器、独立模型资源和真实账号做长稳/压测。
- 并发测试复用发布版工作流，不使用 Mock。

## 注意

- 测试会写入工作流运行记录，但不会创建审批任务。
- 不要在生产租户或真实用户账号上执行高并发压测。
