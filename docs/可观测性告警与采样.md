# 可观测性：告警规则与 Trace 采样

## 1. Prometheus 告警

规则文件：`deploy/observability/alerts.yml`，由 `prometheus.yml` 的 `rule_files` 加载；Compose 已把规则文件挂载到 `/etc/prometheus/alerts.yml`。

已覆盖：

| 告警 | 条件 | 级别 |
|---|---|---|
| `AiAgentBackendDown` | `up{job="ai-agent-backend"} == 0` 持续 2m | critical |
| `AiAgentHighErrorRate` | 5xx 占比 >5%（且总 QPS>0.5）持续 5m | critical |
| `AiAgentHighLatencyP95` | API P95 >2s 持续 10m | warning |
| `AiAgentRateLimitRejections` | 429 >1 QPS 持续 5m | warning |
| `AiAgentDiskSpaceLow` | `disk_free_bytes/disk_total_bytes <15%` 持续 10m | warning |
| `AiAgentDbPoolSaturation` | HikariCP 活跃 >90% 或 pending >5 持续 5m | warning |
| `AiAgentLlmQueueBacklog` | `llmTaskExecutor` 排队 >50 持续 10m | warning |

指标来自 Spring Boot Actuator：

- `http_server_requests_seconds_*`
- `disk_free_bytes` / `disk_total_bytes`（无需额外 node-exporter）
- `hikaricp_connections_*`
- `executor_queued_tasks{name="llmTaskExecutor"}`
- `up{job="ai-agent-backend"}`

本地验证：

```bash
promtool check rules deploy/observability/alerts.yml
# SUCCESS: 7 rules found
promtool check config <temp-prometheus-config>
# SUCCESS: ... is valid prometheus config file syntax
```

**验证（2026-10-26）**：Prometheus/Alertmanager/Alert-relay/Grafana 已随 Compose 全栈实跑；`AiAgentBackendDown` 规则在真实指标条件下 firing：停止后端 >2 分钟后，Alertmanager 经独立 relay 将告警送达测试 webhook（后端已宕机）。

## 1.1 群机器人直接告警（快速路径）

配置（Compose/Helm 同名变量）：

```yaml
alert:
  webhook:
    enabled: true
    url: https://oapi.dingtalk.com/robot/send?access_token=...
    secret: SEC...        # 仅钉钉加签需要
    env: prod
```

- 支持钉钉 / 企微 / 飞书群机器人 text 消息；钉钉 `secret` 按官方规则放 **query**（timestamp + sign），不再放 body
- 成功识别兼容 `errcode=0`（钉钉/企微）与 `code=0`（飞书）
- 故障不影响业务，连续失败只记录一次日志
- 平台管理员可触发真实测试：
  ```http
  POST /api/v1/platform/alerts/test
  Authorization: Bearer <platform-admin-token>
  ```
  返回 `configured/sent`，并写审计 `alert.test`

**验证（2026-10-26）**：单元测试 5/5（文本投递、禁用、钉钉 query 签名、飞书成功码、HTTP 500 不抛异常）；本地启动真实 HTTP 接收器后调用测试接口，返回 `configured=true, sent=true`，接收器收到 text payload。真实群机器人 URL 与值班路由仍需上线前配置。

Helm 未内置 Prometheus Operator；如使用 kube-prometheus-stack，可把 `alerts.yml` 的 rule groups 导入为 `PrometheusRule`，或挂载到现有 Prometheus。

### 1.2 Alertmanager → alert-relay（独立于后端）

Compose 新增 `alertmanager` + `alert-relay`：

```text
Prometheus → alertmanager:9093 → alert-relay:8080/alertmanager
           → 钉钉/企微/飞书群机器人
```

- `alert-relay` 是 `runtime/alert-relay` 的零依赖 Node 服务，单独容器运行；即使后端宕机，`AiAgentBackendDown` 也能送达
- `prometheus.yml` 的 `alerting.alertmanagers` 指向 `alertmanager:9093`
- `deploy/observability/alertmanager.yml` 的 webhook 指向 `http://alert-relay:8080/alertmanager`
- relay 支持钉钉 query 加签、企微/飞书 `errcode/code=0` 成功判断；群机器人失败返回 502 让 Alertmanager 重试
- 后端 `/internal/alertmanager` 适配器保留作手工/应急备用，不再作为 Compose 主链路
- 2026-10-26 实测：停止 Compose 后端，等待 `AiAgentBackendDown` 规则 firing，测试接收器在 **backend 已停止** 的情况下收到完整 text 告警

仍缺：真实群机器人 URL、值班路由、告警抑制/升级策略。

## 2. Trace 采样

配置：

```yaml
observability:
  trace:
    sample-rate: ${TRACE_SAMPLE_RATE:1.0}       # 0..1
    always-sample-errors: ${TRACE_ALWAYS_SAMPLE_ERRORS:true}
```

行为：

- 默认 `1.0` 全量落库，保持现有评测/排障行为；
- 非 1.0 时按 `traceId` 确定性哈希采样（同一 trace 结果稳定）；
- `ERROR` / `BLOCKED` 默认强制保留，避免错误排障数据被采样掉；
- 被采样掉的 trace 不写 `agent_trace`/`agent_span`，也不导出 OTel；
- 采样在 `TraceService.record` 入口执行，所有调用链统一生效。

验证：

- 单元测试 `TraceSamplingTest`：全量、0 采样、错误强制保留、确定性；
- 后端单测 **51/51**；
- 默认 1.0 下完整 E2E 仍通过。

**未验证**：生产采样率下的指标/评测口径影响、OTel 后端采样联动。采样后 Trace 数量本身会下降，仪表盘需按采样率解释。
