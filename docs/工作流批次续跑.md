# LOOP 超限批次续跑

## 行为

- LOOP 项数超过 `maxIterations` 时，先执行上限内的项，不再直接静默截断；
- 生成 `WAITING_APPROVAL`，审批 payload 保存 `remainingItems` 和 `loopNodeId`；
- 审批通过后，把剩余项写回该 LOOP 的 `items`，从同一 LOOP 节点继续；
- 若剩余项仍超过上限，会再产生下一次审批，形成分批续跑；
- 审批拒绝保持原 REJECTED 行为。

示例：

```text
3 项 / 上限 2
→ 执行 A、B
→ 审批（remainingItems=["C"]）
→ 通过后执行 C
→ next
```

## 已验证

2026-10-21 本机真实工作流（Mock LLM）：

- 运行状态 `WAITING_APPROVAL`；
- payload：`remainingItems=["C"]`、`loopNodeId=loop1`；
- 平台管理员携带 `X-Tenant-Id: 1` 审批通过后运行 `SUCCESS`；
- 首批输出 `[1] OK [2] OK`，二批输出 `[1] OK`。

## 边界

- **并行分支审批/嵌套并行仍未实现**；审批节点只在主流程/LOOP 上验证。
- 最终 run output 只保留最后一批循环摘要，完整批次记录需看 node run/审批 payload；后续可拼接历史批次。
- 审批通过会改写该 run 的 definition 中 LOOP items 为剩余项（不改工作流模板本身）。
- 沿用“不能审批自己发起运行”的规则；测试使用平台管理员跨租户审批。
