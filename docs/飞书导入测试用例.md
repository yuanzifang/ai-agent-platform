## 手动/E2E 用例

### FS-01 单文档导入

- 输入：飞书 `/docx/` 或 `/wiki/` 文档链接
- 预期：生成 1 个知识库文档，状态 `DONE`，有 chunk，可被检索命中
- 结果：通过（测试文档 `测试飞书文档rag`）

### FS-02 文件夹导入

- 输入：`/drive/folder/SM1afg2Omlq2Uldb1nYcyhgLn5b`
- 文件夹内容：1 个 docx、1 个 bitable，以及 docx 内链接的 2 个文档
- 预期：
  - docx 和链接文档分别导入
  - bitable 每张表转为独立文本文档
  - 不因个别资源失败中断导入
- 结果：通过
  - 新知识库「飞书多维表格验证」（ID 732）
  - 文档 527～530：`会议记录`、`个人工作日报`、`bbbb`、`✅任务管理`
  - `✅任务管理` 生成 8 个 chunk，检索「组织年度员工团建活动」首条命中
  - 没有 `skippedItems`

### FS-03 正文超链接三级嵌套

链路：

```text

└── 会议记录
    └── 个人工作日报
```

- 预期：3 个文档分别入库，互不拼接；按层级去重；最多三层
- 结果：通过
  - `会议记录.txt`：文档 476，`DONE`
  - `个人工作日报.txt`：文档 477，`DONE`
  - `bbbb.txt`：文档 478，`DONE`
  - 审计记录：3 条 `kb.document.feishu_import / SUCCESS`

### FS-04 超过三层跳过

- 输入：真实四层文件夹/四层文档超链接
- 预期：前三层导入，第四层不发起 API 请求，`skippedItems` 记录原因
- 结果：真实文件夹 E2E 通过
  - 应用自建文件夹：`E2E-三级递归-1/2/3/4`
  - 第 1/2/3 层文档：488 / 487 / 486，均 `DONE`
  - 第 4 层文档：未生成知识库文档
  - `skippedItems`：`超过三层嵌套，跳过子文件夹：E2E-三级递归-4`

### FS-05 长文档分段

- 输入：超过 500 字符的结构化长文
- 预期：
  - 父块约 2000 字符
  - 子块约 500 字符、50 字重叠
  - 表格/代码块不拆分
  - 每个子块有 parentIndex/parentContent
- 结果：`DocumentParserTest` 通过；真实飞书长文 E2E 通过（见 FS-09）

### FS-09 自建长文与四层链接

测试数据由飞书 API 创建：

```text
A（24 段长文，链接 B）
└── B（链接 C）
    └── C（链接 D）
        └── D（第 4 层）
```

- 导入 A，预期 A/B/C 入库，D 不导入
- 结果：通过
  - A：文档 479，`DONE`，7 个 chunk
  - B：文档 480，`DONE`，1 个 chunk
  - C：文档 481，`DONE`，1 个 chunk
  - D：未生成知识库文档
  - A 的 7 个 chunk 内容长度约 337～461 个汉字，低于 500 字符子块上限
- 检索验证：
  - `这是第二层文档 B` → B 首条命中
  - `这是第三层文档 C` → B/C 命中，C 为独立文档
  - `打开第四层 D` → C 首条命中，D 不存在

- 结果：A、B、C 分别作为独立文档入库，未合并到 A 的正文中；D 作为第 4 层被跳过。

### FS-07 权限与凭证错误

| 场景 | 预期 |
|---|---|
| App ID/Secret 错误 | `400`，提示飞书凭证错误 |
| 飞书平台访问策略拒绝 | `400`，错误码 `21001` 可读提示 |
| 文件夹未授权 | `403 / 1061004` 可读提示 |
| 文档无权限 | `403`，提示检查只读权限和协作者 |
