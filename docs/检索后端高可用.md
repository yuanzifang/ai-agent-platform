# 检索后端高可用

当前应用层已支持 ES/Qdrant 多入口故障回退；生产高可用仍需要部署真实集群和负载均衡。

## 应用层故障切换

`ELASTICSEARCH_URL` / `QDRANT_URL` 支持逗号分隔：

```text
ELASTICSEARCH_URL=http://es-1:9200,http://es-2:9200,http://es-3:9200
QDRANT_URL=http://qdrant-1:6333,http://qdrant-2:6333,http://qdrant-3:6333
```

客户端行为：

- 轮询选择起点；
- 连接失败、超时、HTTP 429、HTTP 5xx 自动尝试下一个地址；
- HTTP 4xx 业务错误不盲目切换；
- 所有地址都失败时返回明确异常，由检索层决定降级。

## Elasticsearch 集群

生产建议至少 3 个节点，数据索引设置：

```json
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 1
  }
}
```

关键要求：

- `cluster.name` 一致；
- `discovery.seed_hosts` 指向所有 master-eligible 节点；
- `cluster.initial_master_nodes` 只在首次引导时使用；
- 业务 URL 指向负载均衡或节点列表，不直接依赖单个 Pod；
- 使用 alias 做索引切换，快照仓库使用共享文件系统或对象存储；
- 通过 `knowledge_es_snapshot_*` 指标和 `AiAgentEsSnapshot*` 告警监控快照。

## Qdrant 集群

Qdrant 分布式部署至少需要 3 个节点，并配置共识/peer 地址；生产建议在集群前放 TCP/HTTP 负载均衡，再把负载均衡地址填入 `QDRANT_URL`。

要求：

- 所有节点使用相同 collection 配置与 API key；
- collection 的向量维度/距离/分片参数一致；
- 负载均衡健康检查走 `/collections`；
- 对 collection 做定期快照/备份；
- 不在单节点上假设持久化高可用。

## 验证边界

已在本地验证客户端多 URL 故障回退；真实 ES/Qdrant 多节点集群、跨可用区故障切换和容量规划尚未在本机完成。生产上线前必须做：

1. 杀掉任一节点后的检索持续可用验证；
2. 节点恢复后的数据追平；
3. 快照恢复和 alias 切换演练；
4. 生产规模 ACL/过滤检索回归。
